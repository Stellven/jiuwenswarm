# SIMLAB benchmark and test-bench catalogue

Prepared 2026-10-30 for SIMLAB planning. Versions, maintenance status, licenses and hardware requirements were checked on the web on 2026-10-30 against GitHub (repo pages, LICENSE files, commit feeds), PyPI (latest version, upload date, wheel platforms), official docs and arXiv. Anything I could not confirm is marked **UNVERIFIED**. "Last commit" dates come from GitHub commit feeds or API `pushed_at`.

**Machines**
- **L** = WSL2 laptop: Ryzen 7 8845HS, about 6 GB RAM in WSL, RTX 3050 Laptop GPU with 6 GB (Ampere, x86-64).
- **S** = DGX Spark: arm64 Grace CPU, GB10 Blackwell GPU, 128 GB unified memory, DGX OS 7, CUDA 13.

**Use codes**
- KA = known-answer test bench
- EXT = external comparison
- MIL = model-in-the-loop subject
- WM = world-model evaluation
- BLD = builder-agent or research-agent evaluation
- ENG = engineering test

**Phases:** P1 base simulator · P2 builder + first experiment · P3 libraries · P4 AI4R connection and scale · P5 first research runs · Later.

## 0. Findings to read first

1. **Isaac Sim is out of reach on the laptop, but officially supported on the DGX Spark.** The current requirements page (updated 2026-10-14) sets the x86 minimum at a GeForce RTX 4080 with 16 GB VRAM, 32 GB RAM and 4 cores. The page also says "Isaac Sim aarch64 builds are currently only supported on DGX Spark system" (DGX OS 7, driver 580.159.03), and it lists cuRobo and cuMotion as unsupported there. PyPI has an aarch64 wheel for `isaacsim` 6.2.0.0, uploaded 2026-10-13. Details are in section G.
2. **Isaac Lab 3.0 went GA on 2026-10-20 and no longer needs Isaac Sim.** Its default backend is Newton, which includes a MuJoCo-Warp solver path. The docs say "Headless Newton simulation does not require RTX hardware." DGX Spark is a listed aarch64 platform; it needs CUDA 13 and has some features unvalidated.
3. **MuJoCo already covers part of the planned libraries.**
   - MuJoCo 3.7.0 (2026-04-14) added a `dcmotor` actuator: electrical dynamics, cogging, thermal effects and LuGre friction, with a technical note. It also has a `pid` actuator.
   - MuJoCo 3.17.0 (2026-10-22) added 1D-flex bending as a discrete elastic rod.
   - MuJoCo 3.17.0 also added a batch API whose results are "bit-identical to a plain loop at any thread count."
   - So SIMLAB's motor and flexible-parts libraries should wrap and validate these, not re-implement them.
4. **ManiSkill3 (SAPIEN) does not fit either machine.**
   - The ManiSkill README says WSL supports CPU simulation only.
   - `sapien` 3.0.3 on PyPI has no Linux aarch64 wheel: x86-64, Windows and macOS only.
   - Benchmarks built on it (SimplerEnv's ManiSkill3 branch, MIKASA-Robo, RoboTwin) are therefore external references, not things we run.
5. **The laptop cannot run a released VLA.** openpi's README says inference needs more than 8 GB of GPU memory (example: RTX 4090). Model-in-the-loop work runs on the Spark. Whether openpi works on aarch64 is **UNVERIFIED**.
6. **Several famous benchmarks are saturated, frozen or restricted.**
   - LIBERO is saturated: π0.5 scores about 97% (96.85 in OpenPI, 97.5 reproduced in LeRobot). Its original repo has had no commits since 2025-03. Hugging Face maintains a fork, `hf-libero` 0.1.4 (2026-06).
   - CORE-Bench Hard was declared "solved" in December 2025 (95.5% with manual validation).
   - The MLE-bench leaderboard stopped taking submissions on 2026-04-24.
   - Non-commercial licenses apply to the MIT Push dataset, IntPhys 2, RLBench, the 1X raw video and some ManiSkill assets.
7. **"Gym-Anything for Robotics" exists.** It is arXiv 2610.40565, submitted 2026-10-29, by Aggarwal and Welleck, with MIT-licensed code.
   - It is the closest published analogue to SIMLAB's builder agent: coding agents build simulations, and four audit agents check them.
   - Its runtime is Newton physics plus Isaac Sim 5.1 camera rendering, which needs RT cores.
   - Even the best frontier models average a reward of 0.06 on its RoboWorld test tasks.
8. **Two new 2026 measurement-grounded suites exist.**
   - GAUGE (arXiv 2608.05948, 2026-08) uses motion-capture ground truth to test both simulators and video world models.
   - A University of Colorado paper (arXiv 2603.14634) proposes a solver-agnostic set of seven tests with analytic answers.
   - GAUGE's data and code release could not be confirmed (**UNVERIFIED**).

### A.1 Canonical known-answer cases for SIMLAB's Phase 1 suite

| Case | Analytic answer | What it catches | Existing reference test |
|---|---|---|---|
| Pendulum period | Small angle: T = 2π√(L/g). Large angle: T = 4√(L/g)·K(sin(θ₀/2)), with K the complete elliptic integral. | Timestep and integrator phase error | Drake `examples/pendulum`; MuJoCo docs pendulum example |
| Energy drift with no contact and no damping | E(t) = E₀. The MuJoCo docs say a free spinning body's kinetic energy is "non-increasing" under the implicit integrators, and recommend RK4 for long-horizon conservation. | Integrator choice (Euler, implicitfast, RK4); gyroscopic terms | MuJoCo `ImplicitIntegratorTest.EnergyConservation` and `FreeBodyConservation`; Drake `multibody_plant_momentum_energy_test`; SimBenchmark ANYmal energy |
| Projectile without drag | x = v₀ₓt, z = z₀ + v₀𝓏t − ½gt² | Gravity and integration bias; a baseline for timestep sweeps | Trivial; no external test needed |
| Bouncing ball with restitution e | Apex heights hₙ = e²ⁿ·h₀ | Impact model. MuJoCo has no restitution coefficient; bounce comes from `solref`/`solimp`, so the test validates SIMLAB's mapping from e to solref. | SimBenchmark bouncing test; Acosta et al. cube toss (real) |
| Block on incline (Coulomb) | Sticks if tanθ ≤ μ. Otherwise a = g(sinθ − μcosθ). | Friction cone, stick-slip threshold, creep under soft contact (set a tolerance) | Abderezaei 2026 test 3; Le Lidec ramp-force cube; MuJoCo solver friction-limit test |
| Box sliding to rest | t_stop = v₀/(μg), d = v₀²/(2μg); direction preserved | Pyramid versus elliptic cone bias; energy dissipation | Le Lidec Figs. 9–10 |
| Sphere rolling down incline | Solid sphere: a = (5/7)g·sinθ, friction force = (2/7)mg·sinθ, needs μ ≥ (2/7)tanθ. Rolling resistance with MuJoCo condim 6. | Rolling, no-slip constraint, torsional and rolling friction | Drake `inclined_plane_test` (velocity, angular velocity and friction moment versus analytic) |
| Stack at rest | Zero drift and no jitter over a long horizon; heavy-on-light mass ratios | Solver convergence and conditioning | Le Lidec heavy-on-light; Drake `spheres_stack`; Horak & Trinkle stacking |
| Resting penetration | Steady penetration that is constant and small for the given solref/solimp settings | Contact softness settings; slow sinking | ComFree-Sim penetration tests (2026); MuJoCo solimp docs |
| Spring-damper oscillator | x(t) closed form; ωₙ = √(k/m) | Joint stiffness and damping; implicit damping | MuJoCo `PolyStiffnessEnergy`, `DamperDampens` |
| Cantilever deflection | Small deflection: δ = FL³/(3EI) for a tip load, δ = wL⁴/(8EI) for a distributed load. Pure bending into a circle: M = 2πEI/L. | Flexible-part stiffness calibration | MuJoCo `CantileverIntoCircle`; PyElastica cantilever cases |
| Cable catenary | y = a·cosh(x/a), with horizontal tension H = a·w | Cable and flex stretch, bending and gravity | No engine test found (UNVERIFIED). Compute analytically and cross-check with PyElastica. |
| DC motor step response | Steady state and first-order current and speed dynamics | Actuator library | MuJoCo `DCMotorTest` (steady state, exact integration, LuGre, thermal) |

## H. Contradictions and surprises relative to the planning assumptions

1. **"Built-in motor and actuator models" and "flexible parts" partly exist in MuJoCo already.** These are `dcmotor` (3.7.0), `pid`, cable and elasticity plugins, the 1D-flex discrete elastic rod (3.17.0) and an experimental Stable Neo-Hookean flex (3.15.0). SIMLAB's libraries should be validation and convenience layers over these, checked by the known-answer cases.
2. **"Mainly MuJoCo" now includes the GPU path.** Isaac Lab 3.0 and Newton both use MuJoCo-Warp as a primary solver. A "cross-engine" comparison through Isaac Lab or Newton may therefore be MuJoCo against MuJoCo-Warp. For a genuinely different contact model, use Drake (aarch64 wheels available) or a different Newton solver.
3. **The hardware rules out several "standard" suites.**
   - ManiSkill3 and SAPIEN-based suites: no aarch64 wheel, and CPU-only under WSL.
   - BEHAVIOR-1K: needs Isaac Sim and 32 GB RAM.
   - MLE-bench: canonical setup needs 440 GB RAM.
   - VLA inference: needs more than 8 GB, so not the laptop.
   - The Spark is the only machine for VLA and world-model subjects.
4. **The Ampere laptop GPU has a determinism trap.** JAX uses TF32 matmuls by default on RTX 30/40 GPUs (per the Playground README). Any MJX-based determinism or replay test on the laptop must set `JAX_DEFAULT_MATMUL_PRECISION=highest`. On GPU, MJWarp is deterministic only with sensors disabled, so a full-state checkpoint and replay design that relies on GPU sensors will not be bit-exact.
5. **Cross-machine bit-exactness should not be assumed.** MuJoCo guarantees determinism for the same build on the same machine. An x86 laptop and an arm64 Spark will likely differ in the last bits; the AVX-512 report shows even x86 machines can differ. "Replay" should mean the same machine and build. "Fresh replication" across machines should be judged by statistical or tolerance criteria.
6. **LIBERO is saturated, and its original repo has been quiet since March 2025.** Use the Hugging Face fork and LIBERO-PRO or LIBERO-Plus perturbations, which map naturally onto SIMLAB "interventions".
7. **Some research-agent benchmarks are already solved or frozen** (CORE-Bench solved December 2025; MLE-bench submissions frozen April 2026; PaperBench's repo leaderboard from April 2025). LAB-Bench is biology-only. Better fits for SIMLAB's research loop are NewtonBench and DiscoveryWorld for interactive experimentation, and ScienceAgentBench (verified split) for coding.
8. **No MuJoCo-native cross-episode memory benchmark was found.** The existing ones use ManiSkill3 (MIKASA, within-episode), Habitat, ALFWorld or unspecified simulators. A small SIMLAB-native cross-episode memory task set may be a genuine gap and a possible contribution.
9. **Fresh results to check against SIMLAB's design.** Gym-Anything for Robotics (2026-10-29) has a creation-audit loop with physics checks and a "frontier models fail every test task" result. GAUGE (2026-08) gives measured evidence that no engine (Isaac Sim, Genesis, Newton) is uniformly faithful, especially for impulsive contact, fast textiles and volumetric deformables.
10. **Licenses that restrict reuse:** MIT Push (CC BY-NC-SA), IntPhys 2 (CC BY-NC, evaluation only), RLBench (non-commercial), the 1X raw video (CC BY-NC-SA), some ManiSkill assets (CC BY-NC), LAB-Bench (share-alike) and Isaac Sim (proprietary). Several popular repos have no LICENSE file: PhyWorld, WorldModelBench, LIBERO-Plus, EmbodiedBench and SimBenchmark.
