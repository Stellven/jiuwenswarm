## Summary
Build the phase 1 base simulator as a self-contained Python package and image under `labs/physicalai_sim/`. The first block proves the laptop can host AI4R, a real model-route request and a simulator process together (AC-001, A-13). Then come, in order: the IF-001@r1 contracts (AC-002); authoring tools ending in an immutable manifest (AC-004); validation that returns every finding at once (AC-003, AC-005); a runner that expands the design, keeps every attempt and never judges (AC-006 to AC-008); a pinned MuJoCo 3.17.0 executor confined by seccomp and rlimits (AC-004, AC-019); checks with anchoring and measurement validity (AC-009); world-state save, restore, branch and replay (AC-011, AC-012); a SQLite and NumPy store with queryable traces and provenance (AC-013, AC-014); one JSON-RPC service exposed identically by the Python client, the CLI and an MCP server (AC-015); registry, doctor and resource records (AC-016); check groups in the `deploy/m1/capsule_checks.py` pattern (AC-018); the SIMLAB-Bench F1 and F5 cases with independent stdlib oracles (AC-010, AC-020, AC-021); fresh-checkout reproduction (AC-017); and the phase 1 snapshot and report (AC-022). Decisions and alternatives are in [research.md](research.md).
