## 4. Embedded cross-module agreements

### SIMLAB-IF-001 at r1
Experiment, result and tools. Source: ARCHC "Shared interfaces", SIMLAB-IF-001 (field table is the design contract; this TASK writes the exact schemas). Field names below are canonical for every consumer. Status and enum strings are fixed here. No consumer may add competing shared fields.

| Property | Definition |
| --- | --- |
| Provider and consumer TASK IDs | Provider: PAS-M1-001 (all shared fields, authoring tools, phase 1 operations). Operation providers by phase: PAS-M1-002 (`preview`, `pilot`, `release_inspection`), PAS-M1-011 (`fresh_replication`), PAS-M1-013 (`pause`, `resume`, `stream`), each implemented against this agreement. Consumers: PAS-M1-002, 003 to 011 (add components and registry entries), 012, 013, 014, SYSTEM, and any external agent (US-SL07) |
| Purpose / source requirement | PRD SL-1 to SL-4, SL-7, SL-8, SL-9.D; ARCH X1.3, X1.4, X1.5; ARCHC flows 1, 2 and 4 and failure behavior |
| Inputs: fields, types, units, required/optional, validation | **Experiment** (record `simlab-experiment`, `schema_version` required): `experiment_id` (string, assigned at submit); `objective` (text, required); `objective_kind` (enum, required: `claim_test`, `assumption_test`, `mechanism`, `design_comparison`, `robustness`, `follow_up`, `exploration`; recorded, never judged); `declared_stand_ins` (list of {`stands_in_for`, `stand_in`, `origin`}); `protocol_items` (list of {`item_id`, `item_kind`, `value`, `origin`}; `origin` = source reference with locator, or `requester_declared`; required for every predicate, threshold, arm, variable and trial count); `sources` (list of {`source_id`, `ref`, `sha256`}); `feasibility` (list of {`dependency_id`, `dependency_kind`, `status` ∈ `inspected`/`missing`/`unverified`/`needs_calibration`/`ran`, `reason`, `evidence_ref`, `affected_arms`}); `engines` (list of {`engine`, `version`, `why`}); `resolved_configuration` (every effective engine and runner setting, including timestep, integrator, solver and tolerances; nothing implicit); `assets` (manifest reference: {`manifest_id`, `manifest_sha256`}); `arms` (list of {`arm_id`, `role` ∈ `baseline`/`treatment`/`control`/`reference`/`other`, `components` bound to declared extension points}); `design` ({`factors`, `conditions`, `pairing`, `replicates`, `episodes`, `randomness` (seed policy and declared random variables), `comparisons` (list of {`comparison_id`, `unit_of_inference`, `pairing`, `aggregation`, `required_precision`})}); `procedure` ({`steps`, `events`, `interventions`, `checkpoints` (declared points)}); `measurements` (list of {`measurement_id`, `definition`, `scope` ∈ `trial`/`pair`/`set`, `unit`, `signals`, `required`}); `probes`; `trace_signals` (list of {`signal`, `unit`, `frame`, `rate_hz`}); `checks` (requested known-answer cases, control arms, rerun settings across engine settings and assumed values, independent recomputations; each flagged `required` or not, each with an optional `tolerance` {`abs`, `rel`} against which a recomputed or known-answer value is compared; see §5 A1); `predicates` (requester-declared trial-level conditions evaluated as boolean measurements; never aggregated into a verdict); `thresholds` (carried for the requester; never evaluated by the runner); `limits` (horizon, wall time, numerical watchdog bounds, divergence stop limits, budgets); `deviations` (list of {`deviation`, `reason`, `origin`}); `parent` (optional {`run_id`} or {`checkpoint_id`}). Validation: JSON Schema plus semantic checks; unknown fields are findings; all findings are returned together |
| Outputs: fields, types, units, semantics, guarantees | **Result** (record `simlab-result`): `run_id`; `experiment_id`; `manifest_sha256`; `run_kind` ∈ `original`/`replay`/`fresh_replication`; `parent` (run or checkpoint, when any); `status` (run status); `identity` ({`simlab_version`, `source_revision`, `image_digest`, engine versions}); `hardware` (inventory taken before the run); `trials` (list of {`trial_id`, `arm_id`, `condition`, `replicate`, `episode`, `pair_id`, `attempts` (list of {`attempt_id`, `status`, `invalid_reason`, `seeds`, `started_at`, `ended_at`}), `measurements`}); `cross_trial_measurements` (pair and set scope); `checks` (list of {`check_id`, `check_kind`, `required`, `status` ∈ `pass`/`fail`/`not_run`, `observed`, `affected_measurements`}); `anchoring` ∈ `anchored`/`unanchored`; `measurement_validity` (per measurement: `valid` or `invalid` with the failed check IDs); `model_calls` (IF-004 call records; empty in phase 1); `checkpoints` (list of {`checkpoint_id`, `point`, `state_sha256`}); `traces` (references queryable by run, arm, trial, time and signal); `feasibility` (as executed); `deviations`; `capability_gaps` (list of {`requested_change`, `reason`}); `resources` ({`wall_s`, `cpu_s`, `peak_ram_mb`, `gpu`, `peak_vram_mb`, `disk_written_mb`}); `provenance` (source revision; dependency, asset and model identities; configuration and randomness; package, run, trial and attempt IDs; raw evidence and analysis references); `evidence_level` ∈ `preview`/`simulation`/`measured`/`validated_range`. There is no verdict field. **Authoring:** tools create and change geometry and collision assets, model files, procedures and interventions, measurements and observations, and component code at declared extension points in a draft workspace; `bind` writes an immutable manifest (`simlab-manifest`: every artifact path and SHA-256, extension-point bindings, `experiment_id`). **Operations:** phase 1 `capability`, `validate`, `submit`, `status`, `result`, `query`, `fetch`, `replay`, `cancel`, `branch`; phase 2 `preview`, `pilot`, `release_inspection`; phase 3 `fresh_replication`; phase 4 `pause`, `resume`, `stream`. The MCP server, Python client and CLI expose the same operations with the same inputs, outputs and typed errors |
| States and invariants | Run `status` ∈ `QUEUED`, `RUNNING`, `COMPLETED`, `CANCELLED`, `FAILED` (infrastructure failure only, never a science outcome), plus `PAUSED` from phase 4. Attempt `status` ∈ `COMPLETED`, `INVALID`, `LIMIT_REACHED`, `INTERRUPTED`, `BLOCKED`. `invalid_reason` ∈ `numerical_failure`, `protocol_violation`, `incorrect_intervention`, `missing_required_observation`, `corrupted_record`, `invalid_state_or_action_delivery`; required exactly when status is `INVALID`. Physical divergence is `COMPLETED` (stopped at declared limits). An arm whose dependency is `missing` has its attempts `BLOCKED` with the reason. Invariants: a submitted experiment and its manifest never change; every execution has a new `run_id`; every attempt is persisted; resuming an interrupted trial is a new attempt; pilot runs carry `counts_as_evidence = false`; the runner never writes a verdict |
| Errors, timeout, retry, cancellation | Typed error object {`code`, `message`, `path`, `severity`}; `validate` returns the complete list of findings. `submit` of an invalid experiment returns the findings and creates no run. No automatic retries. Limits end an attempt as `LIMIT_REACHED`. `cancel` sets the run to `CANCELLED`, the running attempt to `INTERRUPTED`, and keeps completed trials. Operation errors use stable codes (catalogue in contracts/) |
| Side effects and idempotency | `submit`, `replay`, `branch` and `fresh_replication` create runs. `status`, `result`, `query`, `fetch`, `capability` and `validate` are read-only. Authoring writes only the draft workspace; `bind` with identical content returns the same `manifest_sha256`. Run data goes to the declared data directory outside the repository |
| Compatibility and migration | Every record carries `schema_version`. Within r1, additive optional fields require an entry in §5 and a consumer notice; anything else is a new revision that updates TASKS §4 and invalidates affected consumer evidence |
| Machine-readable schema / source path | JSON Schema in [contracts/](contracts/) (labeled `simlab-if-001@r1`), mirrored into `labs/physicalai_sim/src/simlab/schemas/` by implementation |
| Provider/consumer verification responsibilities | Provider: PAS-M1-001 plan.md V IDs mapped to AC-002 (schemas), AC-005 (validation), AC-015 (tool parity). Consumers verify the operations they provide or use at their own BOUNDARY level |
| Open agreement questions | None for r1. Operations for phases 2 to 4 are defined here and implemented by their provider TASKs |

Consumed agreements: none. SIMLAB-IF-004@r1 ([PAS-M1-011 §4](../PAS-M1-011/TASK.md#simlab-if-004-at-r1)) defines the `model_calls` records that `Result` carries from phase 3.
