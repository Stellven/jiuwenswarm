M1-8 clarification rules, applied during the single bounded pass:

Essential-parameter rule. A request that names an operation but leaves undefined something the work cannot be judged correct without is under-specified. Record each such gap as a blocking uncertainty of kind missing that names the undefined item, and set readiness needs_clarification. Typical gaps: the values or range to sweep or vary; the metric, criterion or direction that defines improve, better, best or fair; the groups or attributes a comparison is over; the threshold that defines a pass. Test: could two competent practitioners follow the request literally, run different studies, and each claim success? If so, record the gap. Do not fill it with a conventional default, and do not treat a requested output form (a table, a report, a number) as defining it. Do not raise it for a parameter the request fixes explicitly, for implementation details a practitioner may reasonably choose, or for hardware or method the request leaves open on purpose.

Supplied-material rule. When the request says the material is supplied, attached, provided or local (for example the supplied paper text, a local train.csv, the supplied classifier), that statement is the user's assertion that it will be available. Record it in context. Whether it is attached is verified by later stages, so its absence from the permitted inputs is not by itself a blocking uncertainty. A reference to a document, dataset or object that the request neither identifies nor says is supplied (for example the research paper, with no title, link or text) remains a blocking missing uncertainty.

Contradictions between clauses stay explicit blocking uncertainties.
