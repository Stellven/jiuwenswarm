# Fixed expert budget diagnostic component

Fresh A/A speed processes had8957 and8959 GPU expert slots despite identical
flags. This establishes different placement, not its causal role in different
first tokens. The component controls that confounder on a new source revision.
It is a source-bearing CC material package, consumed by the existing guarded
builder and inference job; it adds no alternate engine launcher or GPU authority.

When unset, the new setting adds no allocation, placement change or output.
When set, strict positive decimal bytes through9007199254740991 are accepted.
One CUDA GPU/group/member and static expert caching are required. Existing safe
budget calculation remains authoritative; a request exceeding it aborts instead
of silently clipping. The exact budget includes any loaded draft experts. Model,
expert-profile file, drafting load mode and settings must be pinned together.

Opt-in logging records requested/effective/safe bytes, per-layer resident counts
and FNV1a64 hashes of every expert-to-slot assignment plus an aggregate. FNV is
an identity diagnostic, not an integrity proof. Compare every layer hash and the
native effective chunk across fresh processes. Equal hashes alone do not prove
reproducible kernels, tokens, numerical parity or quality.

Do not rescore the failed original A/A. A new image and contract are mandatory.
A76000000000-byte diagnostic value leaves room below the observed76.99GB but
is unmeasured and may fail safely. Use the same value both A/A arms; changes in
runtime versus the previous image cannot establish a source optimization gain.
Keep any remaining token divergence and report no promotion from diagnosis.
