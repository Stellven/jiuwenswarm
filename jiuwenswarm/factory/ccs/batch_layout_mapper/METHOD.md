# Verification method

1. **fixture** — Run the packaged unit tests. The synthetic diffs exercise apply, allowed scope, forbidden sampling, exact default-off syntax, marker presence, and new-file syntax. The helper tests use synthetic logs, a fake wrapper, and a generated sweep.
2. **native CC execution** — Invoke `verify` using [VALIDATION.md](VALIDATION.md) and inspect every named result. Review the proposed source to confirm that the gate controls eligibility, stock fallback is reachable, and each required marker reaches the intended INFO call. Review router and sampling invariants even when the path guard passes.
3. **compile** — Record the verifier's best-effort C++17 syntax result for a new header. If it skips, retain the reason. Compile and link all affected translation units, including the server context, in the normal engine build for the contract. Standalone example syntax checks cover the examples.
4. **runtime acceptance** — Use an authorized real shell. For each probe compare pristine stock, candidate gate unset, and candidate with `LLAMA_BATCH_LAYOUT=1`. Retain exact generated bytes, ordered token IDs, stop reason, effective settings and raw server logs. Hold model, tokenizer, flags, context, cache policy, greedy settings and request sequence constant within each comparison. With a silent contract, use effective logical and physical limits 13 and 8 and total token lengths **2, 3, 7, 8, 9, 12, 13, 14, 15, 16, 17, 24, 25, 33**. Confirm exact engine token counts including special tokens. For each length run a cold request and a separately primed request sharing `floor(length/2)` tokens. Give the priming request a different continuation or stop it at the intended prefix, isolate each probe from other cache entries, and verify the observed post-cache cursor and stock final-token replay. Use one slot, causal text, and disable speculative, multimodal and checkpoint-dependent paths for these probes.
   - With `-lv 4`, require an active first-use status on eligible treatment probes, contiguous ordered half-open planned spans from the effective cached prefix, and orderly-exit stats. Require at least one case where a logical cut differs from stock. For the ordinary single-stream splitter and `R` uncached rows with admitted physical width `U`, sum `ceil(span_rows / U)` across planned submissions and compare with `ceil(R / U)`. Inspect that the bounds fit the effective reservation and track retries separately.
   - Repeat the longest prompt concurrently with a distinct shorter prompt using two configured slots. Require both outputs to match their stock controls in that same configuration, an inactive multi-slot reason, and zero active layout contributions. Also check invalid gate fallback and orderly-exit stats. Check state size and zero added dynamic buffers against the shared ledger.
5. **hardware measurement** — If the contract requests a speed or memory claim, use comparable stock and candidate runs on the specified hardware and retain raw timing and counters. Actual weight traffic must be measured before claiming fewer physical rereads. Planned microbatch count is scheduling evidence.

Report the highest evidenced stage and any missing evidence. A statically successful `done` verdict requires runtime acceptance before reporting the built component complete. Reporting a speed result requires hardware measurement.

## Gate-unset silence check

Inspect `verify` result `gate_unset_silence` and trace any inconclusive call
through the local code and its callers. Review first use, fallback and teardown for an early
stock return with no component work beyond one cached `getenv` check. In the
gate-unset arm at `-lv 4`, require the saved server log to pass:

```sh
python helpers/check_markers.py candidate-unset.server.log --name batch_layout_mapper --expect-silent
```

Require all component marker lines to come from gate-set arms.
