# Profile-driven expert residency on Spark

Use this method for an explicit profile-driven treatment. Start by reproducing the existing default-off selected-expert copy path and its stock and native-cache bypasses. Compare the profile-enabled treatment separately from the existing dynamic cache. The frozen prior and the measured evaluation workload have distinct identities.

1. Read every completed iteration report and the retained routing profile and transfer analysis. Use the loaded model's hash-bound layer, tensor and expert inventory to check profile compatibility. Admitted profile rows are ordered layer and expert IDs with unique nonnegative IDs, bounded by the loaded model. Require the exact model and profile digests in the run record. Reject invalid, duplicate and out-of-range entries before using the profile.
2. Start with the frozen top-96 list per each of 40 main-model layers. As a bound, this selects about 30.75 GiB of raw expert projection payload for DeepSeek V4.1 Flash. Read actual gate, up and down stride and buffer sizes before allocation. An operator-admitted byte budget includes allocator rounding, staging and cache metadata. Allocate incrementally within the budget and host headroom, and log the exact admitted subset. A subsequent budgeted tier may grow only up to 60 GiB inclusive of overhead. Top-192 already exceeds that budget on raw projection bytes alone. Keep native cache and non-mmap bypasses.
3. Keep nominated slices resident in device memory for the requested lifetime. Charge every admitted slice, use its actual backend, source tensor identity, expert number and representation as the lookup key, and preserve authoritative expert IDs and route weights. First touch can populate a nominated slice from a completed stock upload. Keep unlisted or unadmitted misses on stock coalesced upload segments, including tail padding. On a hit, populate the required scheduler destination from the exact device slice without a repeated host upload. A hit buffer stays alive until the last asynchronous reader. Avoid new synchronization on the hit path unless the backend protocol requires it. Cold demand cannot evict admitted profile slices.
4. Compare capped stock, same-build gate unset and profile treatment with identical model, placement, context, batch, CPU, prompt, cache policy and run order. Use private read-only profile copies. Verify token and output byte parity both on the original fixture and on Spark. Log startup, first-fill and warm phases separately. Confirm enabled hits on real prefill traffic and prove activity independently of the successful return path. Check alternate mappings, invalid input and allocation failure in bounded probes.
5. Record per-phase CPU/GPU transfers, device-to-device hit bytes, fills, misses, actual budget, resident slice/allocation counts, major/minor faults and read volume, plus timings and startup cost. Host upload reduction and CUDA placement are separate observations. A treatment crosses the performance bar only when measured elapsed time improves under a matched quiet comparison. C1 found zero selected-copy bytes in strict-A decode. Do not credit this prefill path with decode improvements. A direct graph-level residency solution requires separate validation.

Implementation material stays method-only. Create the product in an isolated factory task and retain the generated source diff and native acceptance receipt separately.
