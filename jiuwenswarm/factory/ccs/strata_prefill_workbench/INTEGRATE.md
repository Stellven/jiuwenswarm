# Prefill improvement job skill

Use this package for an evidence-driven native prefill improvement job. Its
component description, methods, evidence tools, qualification composition and
bounded execution loop belong to one package. This package normally suffices for
this job; compose another capsule when it adds a distinct useful capability.
The agent chooses what to do next. The shared host retains task authority,
contract admission, durable queue identity, GPU lifecycle and evidence checks.

1. Use `query` and `read` to recover retained reports and decisions. `inspect`
   checks the current frozen prefill contract without running the model.
   `diagnose` surfaces uncertainty; `test_scope` with layer `prefill` and claim
   `configuration_invariant` or `subsystem_performance` identifies the smallest
   useful checks. `ablation` and `followup` propose work; they never admit it.
2. Read `COMPONENT.json`. For this admitted experiment, call `apply` with
   baseline chunk256 and `chunk_tokens: 512` under the fixed full-six static
   profile. The shared transform supports other bounded chunks, but that does
   not admit those settings into this experiment. `verify_profile` checks the requested
   profile; neither proves runtime engagement. When the operator has installed
   a qualification policy for this release, call `qualify_profile` with its
   explicit `policy_id`, `base_profile` and `chunk_tokens: 512`. This saves the
   pair, invokes the independent profile unit checker, and assesses the policy
   in one capability. Inspect its persisted evidence and verdict. A failed or
   blocked result cannot be treated as eligible. Eligibility covers only the
   policy's selected configuration capabilities and never grants GPU use.
3. `design` drafts a new screen or confirm contract from pinned inputs. It
   cannot mutate or admit a contract. Screen is fresh-process AB; confirm is
   ABBA. Publish the observation or versioned decision with `publish`, including
   observations, hypothesis, uncertainty, bounded action, expected evidence,
   budget and stop condition. Operator admission must already cover the exact
   contract or loop template before execution.
4. For an admitted current-task contract, `submit` takes its `contract_id` and
   an idempotency key. Reconcile using `status`; use `result` to independently
   verify retained raw cells. For iterative work under an installed loop policy,
   recover `loop_status`, then `select` a report-backed hypothesis and exact
   admitted template with `expected_rev`. `execute` submits that cycle once;
   replay recovers its attempt. `collect` reconciles and retains child evidence,
   including failures. After a durable submission, END THE AGENT TURN so
   the supervisor can stop control before measurement. Do not poll or sleep
   inside the model turn. On resume, query/read the retained references and
   decide again.
   These are alternative entry points to the same guarded host facilities;
   do not submit the same experiment through both paths.
5. Stop when the scoped objective is met, evidence is insufficient, a guard
   fails, or the authorized cycle/experiment/time budget is exhausted. `stop`
   persists loop stop intent; it does not cancel already queued work. Collect
   outstanding evidence and record why further work is unjustified. Follow-up
   suggestions require a fresh agent decision and any needed operator admission.

Qualification checks only a configuration invariant. Raw native startup counters
must separately establish chunk engagement. Scoped correctness requires the same
single token and finish reason across seven requests and both arms on one pinned
512-token prompt, with EOS and drafting disabled. It does not establish accuracy,
long-form behavior or full-generation quality. Screen yields a trend only.
Confirmation requires complete raw verification, separated process medians and
at least 1.05 arm-median speedup to report a scoped improvement; no result
promotes the profile or grants a general speedup claim. Full-quality integration
requires a separate admitted contract. Keep warmups, failures, OOM/cleanup,
provenance and all raw output even when a candidate loses.
