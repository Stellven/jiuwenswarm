# Residency experiments with a placement plan

The pinned loader places a projection tensor as a whole. A promoted layer owns all of its gate, up and down expert slices. Layer nomination can use a held-out routing prior plus copy volume recorded on an earlier run. Use actual GGUF inventory and allocation estimates to choose a small first layer set, preserve all other expert tensors on CPU and admit the revised plan under the same wrapper and headroom limits. Prove the plan is disjoint from the residual stock CPU override before launching DeepSeek. Validate actual buffer assignments from startup logs.

Run an all-CPU reference with the fixed context, batch and thread profile, a stock `-ot` control with the nominated layer tensors explicitly promoted and the complementary CPU override, and the candidate with the identical allocation implemented through the plan. Compare model outputs across the effective placement change and require candidate-to-equivalent-control parity. Report the policy benefit versus the all-CPU control and the planner's own cost versus the stock equivalent control. Use whole-layer placement as a practical alternate workflow while a separately vetted per-expert cache is being built. C1 copy telemetry and a quiet paired timing run decide attribution.
