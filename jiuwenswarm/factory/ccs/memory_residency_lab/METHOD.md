# Scratch arena liveness methodology

Measure first: instrument every scratch buffer allocation size and inclusive first/last use in the real engine, then convert the final use to a half-open end event. Include asynchronous CUDA completion in end times. Do not infer that host return ends GPU liveness. Persistent weights, KV and residual buffers must retain their real lifetime. Supply 1..128 tensors with positive bytes, integer start/end, unique names and power-of-two alignment. This package does not infer model lifetimes.

`plan` sorts buffers by decreasing size and places each in the first aligned gap among overlapping lifetimes. It reports offsets, arena bytes, sum of independent aligned allocations and a peak-live-payload lower bound. The heuristic is not globally optimal. Offsets are aligned relative to the base; integration must allocate an appropriately aligned base. `verify` independently checks overlap and writes/checks every live region at each event using a real bytearray. `native_experiment` passes only the validated plan through stdin to bundled C++ which independently rejects overlaps, allocates one arena, touches its payload and checks all live bytes. Allocated payload is counted directly; elapsed time includes allocation, initialization, writes and checks and is not an inference latency proxy. Allocator metadata and OS RSS are not counted. The native experiment runs synchronously on CPU and requires no GPU.

Build locally from this directory: `g++ -O2 -std=c++17 native_arena.cpp -o native_arena`. No install or network needed. Invoke native_experiment with EXAMPLES.json request. Use disjoint lifetimes to propose a shared scratch arena; verify actual stream/event lifetimes before editing Strata allocation sites. Keep baseline available and preserve outputs under a full engine test. Revert to independent allocations on any alias/correctness failure.

GB10 has unified system memory; do not sum GPU allocation bytes plus CPU RSS as though they were separate PCIe pools. A scratch arena payload reduction does not by itself prove a resident model becomes feasible: weights, KV, mapping, reclaimability, allocator overhead and page residency remain separate obligations.

First manual round on ARM64, 2026-11-15: native baseline held and touched 31,457,280 bytes in independent allocations; arena held 14,680,064 bytes, saving 16,777,216 (53.33%). It wrote 31,457,280 bytes and checked 35,651,584 bytes without corruption. Diagnostic allocation/touch/check timings were baseline 17.0482 ms and arena 18.2027 ms, with different checking workloads; this establishes memory reuse, not faster execution. Lifetimes are explicit synthetic inputs, not a captured Strata trace. Source and binary hashes and full inputs are in ROUND1.json. Reproduce with `python3 measure_round.py`.

Read-only Strata anchor at local source commit ffa80d73133ea5c548aefe57889a16e8085a938f: `src/dsv41/ds4_model.cu` Dev holds all scratch fields around line 624; `dalloc` around 1965 uses align256 and tracks d.scratch; the allocation chain around 3189 independently reserves attention and expert scratch including xe/xg/xu/xhh/ed. A backend trial should trace these buffer sizes and device event lifetimes and request alignment 256. The package does not assert these tensors are safely disjoint.

Portable packaging: native_arena is excluded from the default package; the measured ARM64 executable is retained separately in runtime-native-artifacts-20261115. Build bundled C++ explicitly on the destination host, then invoke the native capability. Invocation never builds. It checks ELF architecture and reports a clear rebuild error for an incompatible binary. Python `plan` and `verify` do not require a native binary. CPU verification confers no GPU authority. Native byte counts represent held allocation payload; process RSS/physical residency, allocator metadata, base-address alignment and CUDA device memory remain unmeasured.
