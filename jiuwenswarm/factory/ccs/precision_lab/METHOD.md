# Precision calibration and native integration recipe

The custom `reference-symmetric-int4-f64scale-v1` codec is runnable stdlib CPU code. For each block of up to `block_size` values use max-absolute/7 scale (zero block uses scale 1), nearest-even rounding, clamp to [-7,7], signed two's complement nibble codes and low nibble first. Code 8 is reserved; an odd final high nibble is zero. Scales are represented as JSON float64 values and counted at 8 bytes each in storage calculations; JSON transport itself is not a binary tensor format. Decoder validates count, block size, scale finiteness/positivity, payload bytes, reserved codes and padding. Tiny underflowing scales are rejected. There is no GGUF/GGML/EXL2 binary compatibility or CUDA kernel.

`quantize` returns actual packed bytes, scales and decoded values. `evaluate` reports normalized, overflow-resistant RMSE/max absolute error with explicit absolute budget, plus separate exact and approximate gates. Identical zero tensors pass the exact gate; any reconstruction difference is a numerical change even if within budget. `calibrate` chooses the lowest reference storage among candidate block sizes passing the supplied tensor budget, or null if none pass. This is calibration on supplied values, not held-out task quality, language model perplexity, or model accuracy certification. Keep calibration tensors separate from evaluation tensors, bind their hashes/shapes to the candidate, and test zeros, signs, extremes, outliers and malformed payloads. Do not promote by tensor error alone.

`memory_plan` counts reference INT4 weight payload plus float64 scales. It separately labels quantized KV payload approximate and excludes its scale/zero-point/alignment overhead. Conventional KV elements=batch*tokens*layers*kv_heads*head_dim*2; DeepSeek MLA has a different compressed cache layout and must use actual engine allocation sizes instead. Weight-only and KV precision changes require distinct experiments. Neither permits CPU/GPU memory capacities to be summed on GB10.

Native integration seam: at model tensor load identify each expert tensor's name, dimensions, baseline dtype and format; retain an immutable baseline artifact and bind a quantization recipe/calibration hash. Select only an ARM64 and GB10-supported format/kernel pair after validating loader type/stride/block-layout checks. At expert matmul dispatch verify the selected kernel actually receives quantized blocks and scale arrays, not dequantized fallback data. Record kernel counters and synchronization. Keep router, attention and output head unchanged for a weight-only experiment. KV candidates instead modify cache allocation, writer, reader and attention kernels coherently, retain positional/sequence bookkeeping and never reinterpret baseline bytes under a new dtype. No hook is patched by this package.

llama.cpp/ggml demonstrates block formats and backend kernels; ExLlamaV2 offers GPU-focused quantization ideas, not a portable GB10 guarantee. FlexGen and ZeRO-Inference compression/offload recipes are workload specific. SOURCES.json records exact fetched repository revisions and license metadata, and explicitly distinguishes unpinned papers and ambiguous LiteMoE projects. No source code or benchmark ratio is copied.

Promotion requires held-out model outputs/quality under an explicit operator budget, unchanged expert routing unless independently authorized, full memory and throughput measurement, supported kernel dispatch evidence, and rollback to baseline tensor/cache formats. Numerical changes never enter the exact optimization gate. All current qualification is CPU reference only; VERIFICATION-UNITS.json is a local test map, not a factory qualification checker registration.
