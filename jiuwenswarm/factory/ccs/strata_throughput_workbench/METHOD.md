# Bounded native throughput job

Use this package to investigate actual Strata throughput through one coherent job:
recover evidence, inspect native mechanisms, construct and check profile pairs,
read frozen designs, choose an admitted experiment, collect its raw result, and
revise the hypothesis. Shared host facilities enforce authority and lifecycle.

Version 1.1.1 preserves `DS4_EXPERT_BUDGET_BYTES=76000000000` as
source-qualified fixed-placement profile context while transforming one existing
finite setting. `apply` cannot set or change that budget. The legacy drafting
component remains unchanged. This preparation/verification adds no source, image,
build, experiment, GPU or promotion authority: the exact admitted v4/v5 template,
build provenance and independent raw baseline qualification remain required.

`apply` accepts base_profile, setting and an integer value. inspect lists the
finite surface and required engagement. CPU, Engram, lookahead, drafting and
chunk treatments are hypotheses; unchanged or unexercised settings are not gains.
`verify_profile` requires both base_profile and candidate_profile and checks the
exact one-setting transform. It is not independent domain qualification, runtime
engagement, scientific acceptance, or a GPU grant.

`design(template_id)` reads the exact hashed broad-benchmark template installed
in this task loop policy. It never generates new admission. Historical benchmark
contracts remain unchanged. New broad screens use sampled quality plus native
prefill/decode combined throughput. A screen is exploratory; independent balanced
confirmation and its frozen quality gate are needed before a scoped acceptance.
Chunk parity failure and prior drafting prefill cost remain retained evidence.

The wrapper exposes evidence query/read/publish, methods diagnose/ablation/followup/
test_scope, and loop_status/select/execute/collect/stop. These are constant routes,
not arbitrary subprocess or backend selection. Only execute declares gpu.use.
Do not launch GPU work directly, modify host settings, or infer admission from a
profile check. Stop admission early enough for the task hard deadline and cleanup.

## Inspect the retained evidence after collection

After `collect`, call `inspect_evidence` with the same `cycle_id`. This verifies
only this parent's ledger-owned benchmark child and imports allowlisted raw
stdout, stderr, resource samples, recorder report and pipe events into parent
artifacts. Read the returned artifact IDs using this package's `read` capability;
do not query a child task directly. The summary exposes effective expert slots,
CPU expert counts, native per-request rates/draft counts, lifecycle CPU/I/O and
sampled memory. Lifecycle resources include startup and are not decode-causal
measurements. Missing request TTFT, GPU utilization and kernel memory peaks stay
unknown. Collected failed/cancelled cycles can expose sealed partial diagnostics;
partial or archive-only evidence never establishes complete execution or scoring.
Reinspection verifies source hashes again and never overwrites historical copies.
