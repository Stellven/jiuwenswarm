# Expert Weight Streaming Builder 1.0.3

`ranges(inputs)` validates the fixture schema against the exact upstream source seam. It preserves authoritative selected IDs, including repeats, while deduplicating byte reads. Bounds use original GGUF shard/data offsets, contiguous expert stride and original packed formats: F32, IQ1_M, IQ2_XXS, IQ2_XS, Q4_K, Q5_0, Q8_0. The pinned V2-Lite Q4_K_M asset mixes all three latter layouts in routed tensors; qualify each ARM reader before activation. Packed block scale/metadata bytes travel unchanged. These declared shard digests must be checked against independently admitted assets; the planner does not authenticate model files. Model loader registration obtains fd/offset directly from resolved GGUF metadata, not these declarations.

`integration(inputs)` returns the source pin and material contract. In a clean owned checkout at that pin, apply integration_patch; place streaming_source at ggml/src/ggml-cpu/expert-streaming.cpp and streaming_api at ggml/include/ggml-cpu-expert.h. Obtain residency_header from the separately sealed engine.expert_weight_residency_builder release and place it at ggml/src/ggml-cpu/expert-residency.hpp. Place both CPU fixtures and check-cpu.sh in tests/demo-expert-weights. Record both sealed releases and actual material hashes in source provenance. The patch binds acquisition after authoritative routing and holds each thread's generation lease through the final ordinary CPU/tiled reader. The compact tiled tensor is a local view; selected IDs, row map, mixture weights and kernel arithmetic remain unchanged.

Activation is startup-only: both LLAMA_EXPERT_RESIDENCY=1 and LLAMA_EXPERT_STREAMING=1, plus every effective_environment field returned by the admitted residency plan. Require --load-mode mmap --lazy-mode on, explicit expert override 'blk\.[0-9]+\.ffn_(gate|up|down)_exps\.weight=CPU', no mlock/direct I/O, no draft model. Require scoped LLAMA_ARG_REPACK=0 and LLAMA_ARG_NO_HOST=1 (equivalent to --no-repack and --no-host) on matched stock/OFF/ON arms. The CPU override alone can select GPU host or CPU extras. Ordinary mmap tensors use the pinned CPU_Mapped wrapper; registration admits exact CPU and CPU_Mapped type identities, never buffer names or generic host predicates. CPU_REPACK/CUDA experts are rejected. CUDA host compute/output buffers may still exist; verify model buffers separately. The runtime validates the warm set against loaded tensors; invalid/mixed switches, unsupported layout or impossible budget fail. Oversized, busy or fully leased slots bypass to the original mapping and increment bypass. Short/failed reads or cancellation fail acquisition; the graph aborts rather than returning successful output. No prefetch or Engram interception is installed.

Rollback: collect artifacts, stop and join the owned process/readers, destroy its context, then restart the same candidate with both switches 0 or unset and otherwise identical arguments/assets. There is no hot toggle, cache resize or shared-service restart. Default-off does not create a registry. Keep stock A and same-candidate off A-prime as separate controls.

Counters: successful fills, cache hits, joined fills, explicit bypasses, failed fills, current/peak owned bytes, outstanding I/O bytes and active leases. They describe application reads, NOT physical disk traffic or critical-path waits. A timing profile and phase-tagged route capture remain prerequisites for performance claims or CC 3. Final log is a teardown snapshot, not proof of per-request engagement. CPU fixtures prove byte fidelity and exact routed outputs on the ARM ordinary vec-dot reader, including slot-pressure fallback while a lease remains held. Upstream disables tiled eligibility on ARM even with the force flag. The local compact tiled view is source-only and not execution-verified here; AVX-host validation is required before claiming tiled support. No whole-model or greedy-token acceptance is inferred.

For an already integrated mixed-format candidate at 064ca7c10aa4b49d1a20f84d6ae703fe6e99186d, use mapped_upgrade instead of reapplying the upstream patch. Its exact parent and before/after hashes cover the loader edit and three material writes. Clone into an owned checkout, read the sealed materials, apply through source_workbench, retain receipts and commit before Builder. The CPU fixture checks both accepted concrete types, null rejection, forged host names and actual CPU extras, then original packed consumers and rollback. CPU fixtures do not establish live engagement or model correctness.
