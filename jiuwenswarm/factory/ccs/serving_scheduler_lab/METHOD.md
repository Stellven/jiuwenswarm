# Bounded serving experiments

`schedule(spec)` takes `requests` (unique string id, positive prompt_tokens, nonnegative decode_tokens, optional arrival tick), positive token_budget and prefill_chunk, optional max_active (default 16), max_steps (10000), and prefill_reserve (default 1, <=budget). Admission is FIFO by arrival with stable tie order and at most max_active requests. Each tick first schedules ready decodes round robin, one token per request, reserving prefill_reserve if prompts wait. Remaining budget runs prefill round robin in chunks. A newly finished prefill decodes on a later tick. Decode priority therefore has a finite reserved exception to avoid prefill starvation. Reserve zero can starve prefill under unbounded arrivals; budget one with reserve one pauses decode while prefill exists. All finite bounded requests eventually finish given enough max_steps; truncation returns unfinished IDs explicitly.

`analyze(spec)` takes trace and token_budget, optional prefill_ms_per_token and decode_ms_per_token. It validates token accounting and returns phase totals, budget utilization and a cumulative additive timeline. Costs are caller assumptions, with no overlap, hardware bandwidth or kernel prediction. It reports timing_measured=false. `compare(spec)` takes workload with schedule fields, arms (1..8 scheduler parameter dictionaries), optional costs. Arms may vary only token_budget,prefill_chunk,max_active,max_steps,prefill_reserve; request shape stays frozen. Compare long-prompt/short-output, short-prompt/long-output, bursty arrivals and mixed shapes separately. Keep incomplete arms visible.

This schedules work units without changing logits, checkpoint top-k or activated experts. Chunked prefill requires the target engine's attention masks/positions and KV semantics to preserve exact outputs; schedule equality alone proves no model accuracy. AdapMoE adaptive gating changes expert activation and belongs to an independently admitted approximate contract. PowerInfer-2's smartphone CPU/GPU/NPU and flash execution assumptions require measured GB10 adaptation; they are not a drop-in serving backend.

Before runtime integration freeze weights/tokenizer/template, routing, seed, workload arrivals and output lengths. Capture prefill/decode events, admission queue wait, first-token latency, inter-token latency, total latency, throughput, KV memory and failures. Keep CPU trace estimates separate from GPU observations. Nonzero finite-job completion checks establish reference fairness only; continuous-arrival SLOs require admission/load bounds and actual service costs. Runtime installation, ARM64/GB10/model compatibility and factory qualification remain unknown.
