# Investigate an inference lab result and design the next intervention

Use this package when the job starts with retained measurements, a failed observer,
or an uncertain optimization and should end with an evidence-linked next input,
an explicitly admitted bounded test, or a justified stop. Its analysis, candidate
components, evidence tools and experiment controls serve that one job. Choose only
the tools needed; the steps below are decision points, not an obligatory pipeline.
No separate methodology or evidence capsule is required.

1. Use `query` to find current-task reports and `read` to inspect raw records.
   Delegated evidence remains limited to host-granted tasks. Preserve failed cells,
   observer perturbation, missing counters and model/image/workload identities.
2. Use `diagnose` for report-backed uncertainty, `test_scope` for the claim's smallest
   useful verification scope, `analyze_profile` for retained native/Nsight artifacts,
   or `evaluate_prediction` for a bounded offline trace. Unknown measurements remain
   unknown. A profiler result is diagnostic evidence, never an untraced speed score.
3. Choose a falsifiable hypothesis. `propose` records an agent-authored unmeasured
   hypothesis with provenance; `ablation` designs one variable; `cache_protocol`
   separates fresh process, prompt reuse and file cache. `followup` produces a next
   input without changing a contract. Cite report IDs rather than inferred successes.
4. When the mechanism fits, use `apply_prefill` or `apply_drafting` with an exact
   baseline profile. Read COMPONENTS.json and INTEGRATION.md first. These are usable
   configuration components with existing engine mechanisms; expected benefit is
   unknown. Keep each candidate separate from baseline, and test one variable first.
5. Publish the candidate, rationale, counterfactual, verification obligations and
   `followup` output as a `methodology_proposal` observation or artifact via `publish`.
   Keep original evidence immutable. A saved proposal is a useful completed result
   when admission, source identity or measurement prerequisites are missing.
6. If the task already admits the exact experiment, inspect `status`, then `select`
   the allowed template and `execute` its cycle. `qualify_prefill` can check a candidate
   under a supported explicit operator policy; it does not grant execution. For an
   admitted native observer planned by `profile_plan`, use `lab_submit`, `lab_status`,
   `lab_result`, and, if necessary, `lab_cancel` with owned attempts. Queue submission
   requires its declared effects and the existing host admission/resource checks.
   End the agent turn for quiet measurement; `collect` resumes from durable evidence.
   Retain failures, cleanup receipts and raw counters before deciding again.
7. Compare evidence at its declared scope. Choose independent confirmation, a revised
   hypothesis, a prerequisite handoff, or `stop` with a reason. Stop prevents future
   loop dispatch and does not cancel queued work; use `lab_cancel` only for an owned
   lab attempt. No tool here automatically promotes a component or relaxes quality.

## When a new lab run is justified

Start a new admitted run when the current evidence cannot falsify the chosen
hypothesis: missing runtime engagement, observer gaps, failed cleanup/repeatability,
a new candidate setting, independent confirmation, or a changed workload/model/image.
Reuse sufficient retained evidence for pure analysis instead of launching a duplicate.
The operator freezes a new comparable run set for any changed evaluation contract;
a generated profile or followup proposal never amends the current scored contract.
Use existing loop templates only when the hypothesis and exact candidate are admitted.
If no matching template/policy exists, save the next input and hand off for operator
admission. Source changes/builds, new profilers or kernels, unsupported components,
and authority outside the task require an explicit prerequisite handoff. Do not
turn an analysis call into an implicit GPU run, build, install or wider grant.
