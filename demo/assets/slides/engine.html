The engine problem

One token through a 35B MoE on an 8 GB Jetson

Qwen3.6-35B-A3B: 40 layers × 256 experts, 8 chosen per layer per token. Experts are 18.3 GiB of a 20.8 GiB file; the machine has 7.4 GiB of shared memory.

Stock llama.cpp cf34d311 · -ngl 99 -cmoe -lm mmap (configuration)

GPU: attention and router for layer L (2.5 GiB, resident)

Router picks 8 experts: about 15 MiB of weights for this layer

CPU expert matmul touches mmap’d pages. Not resident → page fault → compute thread waits on NVMe

With expert streaming (software: patches to llama.cpp; switches set by env)

Hook before layer L’s expert matmul sees the router’s choice

Demand fill: 16 workers read only the missing ranges

Predictive read: guess L+1’s experts, read while L computes

Same matmul finds the weights in memory

Unchanged: weights, math, router choice, sampling. Wrong guess = wasted read; late read = demand reads the rest.

Not expert placement: experts stay CPU-side (-cmoe). We change when and how their bytes are read, not where they run.

Hook: ggml_backend_sched_set_cpu_callback → llama_context::expert_prefetch_cb; reads via ExpertFiller using llama_model::expert_file_info. Figures from the GGUF header and /proc/meminfo.

Each generated token runs 40 layers. In each layer, attention and the router run on the GPU because -ngl 99 puts all non-expert weights there. -cmoe keeps the 256 experts per layer on the CPU, backed by the memory-mapped model file. The router picks 8; the CPU matmul touches only those 8. If their pages are not in memory, the compute thread takes page faults and waits for storage. That is the bottleneck: about 586 MiB of expert weights per token, and only part of 18 GiB fits. Expert streaming adds a hook just before each layer's expert matmul. Demand fill checks which of the chosen experts' pages are missing and reads them with 16 workers in 2 MiB chunks. Predictive read applies the next layer's router to this layer's input, guesses its 8 experts and reads them in the background. The matmul is the stock code. If a guess is wrong we wasted a read; if it is late, demand fill reads what is missing. Output is unchanged because nothing writes weights and routing is the stock top-k. What is configuration: -ngl, -cmoe, mmap, and the env switches. What is software: the patches.
