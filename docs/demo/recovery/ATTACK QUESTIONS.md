# 20261113 Demo Attack Questions prepresentation

| Question | Answer grounded in this demo |
|---|---|
| How did you find this? | Through prior source inspection, integration and lab observations, packaged into expert-streaming guidance and components. Open SOURCE-MAP.md and the evidence. The recorded factory run demonstrates reuse, not autonomous invention of the original method. |
| Is a CC just a patch? | Components carry patches, but the capsule also specifies applicability, evidence interpretation, prerequisites, runtime switches and stop rules. The agent performs integration; builder and lab capsules provide separate execution capabilities. |
| Why not use Codex and a script? | That is a credible alternative. Here the added value is reusable guidance plus durable task/build/lab records and traceability. We have not run a controlled comparison proving this is faster or more capable than raw Codex. |
| Is the ontology decorative? | The new optional engine-slice field validates the named target and carries it into work nodes. It does not semantically prove arbitrary code edits or replace agent judgment. Historical results predate this added linkage. |
| Did this video achieve the headline? | No. It shows the fresh 32-token fill-only process, which was inconclusive. The headline is the separate recorded 64-token J-OM13 experiment with fill plus predictive reads. Both complete sources are provided. |
| Is the model now accurate? | This work checked byte-identical continuation on a fixed greedy workload. It does not establish general model accuracy or quantization quality. |
| Why this model and machine? | The model's expert weights exceed available memory, creating a concrete weight-readiness problem. The method targets that operating regime; a fully resident model may gain little. |
| Did you just enable everything? | No. Fill had dormant source prerequisites; predictive reads are a distinct intervention. Inspect source and runtime switches separately. |
| Where is the improvement happening? | Expert weight availability before CPU expert matmul. CPU/GPU placement is unchanged in this story. |
| Why not show a larger gain? | We present the selected matched comparison and preserve all arms. We are demonstrating an implemented capability, not maximizing a headline by selecting individual runs. |
| What is left for RSI? | Better reusable selection rules, adaptive policies, applicability ranking and evidence requirements. The cc-rsi-v1 reference remains immutable; later factory linkage changes are separately pinned. |
| Is recovery now automatic? | Worker restart and interrupted-job reconciliation are tested separately. Full unattended boot depends on the installed service and login/linger prerequisites recorded in VALIDATION.md. We do not claim immunity to power loss. |
