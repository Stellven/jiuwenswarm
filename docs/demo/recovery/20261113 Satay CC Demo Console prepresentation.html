Two engineering details from the actual work

What we learned building this

1 · Present in source ≠ switched on

In the agent task that built the headline image, switching the two prerequisite components on made decode slower: mmap_advice 894 → 1825 ms/token, router_prefetch 928 → 1494. Both were rejected as speed-ups. But fill runs inside the hook that router_prefetch adds.

So the agent applied the capsule's dormant-prerequisite rule: keep their source, with switches off in every later run. Then fill (+11%) and predictive reads (+12.5%) each passed their own gate.

Consequence: dependencies and switch states are recorded, checked capsule data. Enabling every patch would have made decode much slower. A script could encode the same rules; the capsule is where they are written, versioned and found.

2 · A compiler can spoil a measurement

On 10 Nov a lab run was declared unscored because a C++ build was compiling at the same time; memory pressure also tripped the run watchdog's swap-rate limit. Repeating runs would not reveal that kind of contamination.

Fix: GPU and build jobs share one queue and never overlap (siminfeng 585cb23). Compiles are routed into that queue, every run records contention, and a contended run is unscored (e410103). Factory jobs use the same queue (5b2830fb).

In the fresh task: all 12 confirmation runs record host_contention false. J-OM13 predates contention recording.

Spare detail: a requested setting isn't proof of the effective one. One historical run asked for K=10 and silently ran K=8, so the factory now compares requested and effective configuration. Sources, commits and tests · Agent task bd173c08 timeline
