The primary objective of M1 is to establish the core architecture and restricted domain functionality. While this document outlines the comprehensive feature set (including test report requirements and ongoing AI research tracks), M1 strictly bounds implementation to foundational scaffolding and default states to ensure a rapid initial iteration. That being said, all functionality in the current AI4Research project will be either implemented, created but not wired in, or taken into consideration in the design to integrate in future milestone stages.

## 2. Domain Policy & Restrictions (M1)
To maintain velocity for next week's kickoff, the following rules govern M1 development:
*   **Default Over Dynamic:** Complex orchestration will rely on static defaults (e.g., default DAG selection) at first to initially debug and build workflow, once past that stage within M1, the autonomous agents that are developed in parallel to plan DAGs will be integrated.
*   **Concurrent Unblocking:** Parallel tracks (like RSI or model routing) will be tested against static sample data (Sample DAGs) built during static default DAG stage to avoid integration bottlenecks until they are verified to integrate.
