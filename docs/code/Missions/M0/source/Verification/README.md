# Intention Compiler verification route

Use the required proof table in [Architecture Main](../Architecture_main_body/Architecture_main_body.md), then the boundary obligations, examples and authoritative contracts linked from [Architecture Context](../Architecture_context/Architecture_context.md). These define verification for the whole compiler and its foundations, through accepted Research Brief or attributable halt.

Test the usable positive path and failures: unusable/contradictory interpretation, unsupported additions, permissible omissions, malformed work/verdicts, stale subjects, invalid resources/defaults, aggregate limits, model/persistence failure, restart, cancellation, browser disconnection, container startup, readable exports and bounded downstream compatibility. Preserve exact inputs, candidate identity, commands, expected/observed behavior and evidence. Fixture-only semantic checks do not prove configured-model behavior. BLOCKED and NOT_RUN are not PASS; a correct failure halt does not replace positive completion.

Do not implement downstream research, RSI, advanced compilation or sidecar tooling. Report runtime evidence separately from documentation checks. Follow the coding experiment owner's usage reporting instructions; unavailable telemetry is not a measured zero.
