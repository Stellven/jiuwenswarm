# Offline RSI: a separate, reusable improvement path

**Reading level: human potential.** Question answered: How can implementations improve outside the live research DAG?

## Responsibilities and semantic connections

| Responsibility | Inputs / outputs | Boundary |
|---|---|---|
| Target profile | Eligible immutable parent, explicit mutable files/paths, fixed contract, visible tests, fixture split identities, scoring adapter and improver settings | Target-specific content stays here. Shared engine does not branch on a capsule name. |
| Session controller | Profile, frozen policy/evaluator/configuration, resource budget / session and ordered attempts | One bounded candidate change per iteration; no production DAG participation. Parent/child use comparable effective settings. |
| Proposer | Authorized implementation copy, visible failures and approved aggregate feedback / candidate change and rationale | No hidden cases, oracle secrets, gate/check edits or activation permission. |
| Write guard and isolated child runner | Candidate diff and parent contract / allowed candidate plus visible/parent-test results, or refusal | Trusted enforcement outside mutable code; validate full affected dependency closure. A declaration cannot grant more authority. |
| Fixture oracle and independent referee | Exact parent/child and sealed split identity / permitted counts and protected scoring evidence | Custodian owns hidden data, scoring and lifetime query count. Child runs cannot read expected outputs or the fixture store. |
| Evidence/export builder | Session, attempts, parent/child identities, scoring, limits and violations / reconciled report and allowed paired records | Raw evidence is protected; proposer receives only its permitted view. General export never copies hidden content. |
| Admission and human activation | Candidate, lineage, compatibility and protected evaluation evidence / admitted inactive version or refusal | Explicit human selection affects future runs only; preserve rollback. Target 1's M1 deliverable remains sandbox child/evidence, not a changed live sum/ranking policy. |

## Data needed from day one

Keep parent/candidate declaration and implementation identities, interface/frozen-contract identity, target profile, diff/rationale, improver version/policy, evaluator/scoring/split identities, model/configuration identity, call/time observations, visible and protected comparison outcomes, query counters, stop reason, violations, admission and activation history. Associate all evidence with session/attempt and applicable run/export provenance. Record unsupported fields as unavailable, not invented measurements.

## Future recursion without weakening the referee

Version the improver's proposal policy, target selection, context recipe and decision evidence now, even though M1 keeps them fixed. A future eligible improver change is itself a candidate evaluated on held-out **improvement tasks**, with improver-quality measures separate from capsule score. The improved component must actually drive later rounds to justify a recursive claim. Keep referee, hidden-suite author, oracle, hard limits, security, contracts and evidence authority outside both mutation levels.

## Approved reference retrieval

“Offline” means outside the live research DAG, with controlled isolated evaluation; it is not an absolute ban on approved reference access. Latest §§1.3/4.4.9 permit allowlisted read-only public benchmark/repository retrieval. Protected preparation records origin, license/provenance, immutable revision/content hash and local snapshot before session use. Public references remain separate from hidden-loop/final data; no uncontrolled network, external write or hidden-data transmission is authorized. A missing approved reference blocks only the dependent profile; locally prepared Target 1 fixtures need not wait for network access.

## Integrity and session clearance

Trusted RSI capture maintains ordered hash-chained attempt records: session/attempt sequence, previous-record hash, exact candidate/parent identity and evidence/outcome references. Define a pinned serialization/hash profile; the first record identifies the chain root. Before admission, verify chain continuity, lineage resolution and that reported scores reconcile with custodian evidence. The proposer cannot author protected observations or replace a prior record. Missing/tampered history blocks admission.

## Target 1 scoring and headroom

Target 1 preserves sum-of-three scores, stable ascending-ID ties and Top-1 output. Mandatory parent tests, port/effect compatibility and mutation limits pass before hidden evaluation. The frozen scorer orders children by **hidden passed-test count first; time only when counts are equal** (§4.4.2). Correctness improvement and secondary timing improvement are reported separately. Timing cannot compensate for fewer passing tests.

Protected preparation fixes host/runtime, workload sizes and identical parent/child batch iterations. Run five warm-up batches and seven paired rounds, alternating execution order, then compare medians of paired batch durations. For equal counts, require at least 10% relative time reduction and a gain greater than three times calibrated relative timing noise. Hard resource limits still apply. These selected policy values require calibration evidence; they are not measured truths. The profile pins them before proposing code.

Calibrate with planted good/bad children under the unchanged interface and hidden-suite custody. A correct parent can be eligible through demonstrated secondary timing headroom; a parent with no measurable correctness or timing headroom is BLOCKED. Do not weaken a production parent, invent passing cases, adapt hidden tests or adjust thresholds to obtain improvement. If small workloads cannot be measured reliably, use a predeclared larger batched workload within the helper's interface and fixed resource budget before the session, or block. No claimed guaranteed improving child.

The proposer sees only passed/total/queries-left from hidden-loop scoring, plus visible development observations. Protected final comparison is once per session. Authorized terminal export may expose paired aggregate counts/times and limits, never case IDs, expected answers or hidden contents; exported final evidence cannot return to proposal context. Admission checks this same record and preserves inactive standing. Live production ranking remains unchanged in M1.

## Connected behavior summary

Target 1 improves a sandbox copy of Screening's pure `rank_opportunities`, preserving incoming dimensions/interface/target policy. Live production remains unchanged. Target 2 implementation text/work rubric is conditional on bounded headless model support; verifier/referee rubric stays frozen. Required Target 1 does not wait for a finished planner.

Protected target profile pins parent, allowed mutation/dependency closure, frozen contract, visible tests, split/scoring/improver/settings and limits. Session controller bounds ordered proposals; proposer sees only authorized development context. Trusted guard rejects forbidden changes; isolated child runs required tests. Independent custodian/referee owns hidden-loop/final fixtures, counters/scoring and comparable paired parent/child evaluation. Security fault stops session; ordinary candidate decline can feed bounded loop.

Separate development, hidden-loop, hidden-final and milestone data with overlap checks. 30 hidden-loop queries/session, 90/loop-set lifetime; feedback only passed/total/queries-left. Final once/session, withheld from future proposals. At least 20 cases/hidden split; 10 known-bad and 3 known-good calibration children; preserve required headroom/repeated-fixture aggregation and paired comparison, not voting shortcuts.

Retain lineage/diff/configuration/contract/referee/scoring identities, observations/counters/violations/stop reasons and allowed paired evidence exports. No hidden reads/leaks, permission growth, referee/contracts/evidence mutation, automatic activation or live installation. Required guardrail suite includes custody, tampering, resource abuse and promotion bypass. Admission checks integrity/compatibility/allowed change/tests independently of score; human-controlled sandbox standing/activation/rollback demonstrated without changing live ranking.

Approved public references may be retrieved read-only by protected preparation with origin/license/revision/hash snapshot, separate from hidden fixtures. Offline means outside live DAG, not uncontrolled network. Proposer model calls use audited boundary and separate audience/budget. Future improver changes require held-out improvement-task evaluation; M1 improver/referee remain fixed. [RSI fields](reference/other-contracts.md#offline-rsi-records) define all records.

Trusted ordered attempt logs are hash-chained with sequence/root/previous-record hash and pinned hash profile. Admission verifies chain continuity, parent lineage and scores against custodian evidence. A security halt requires recorded human clearance and validated remediation before a new autonomous session; no waiver or deleted history. Frozen target profile specifies improvement measure/minimum delta/headroom rule; planted-child calibration must demonstrate attainable improvement, or block the target. Numeric query/fixture limits are retained architecture policy, not verbatim latest PRD numbers or proven optima.
