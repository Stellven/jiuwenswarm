### 4.7 Intention Compilers

Keep a self-contained one-shot research compiler with fixed interface/defaults as the permanent Phase 1 fallback. The external advanced compiler integrates in Phase 3 through compatible task contracts. Neither fallback semantic extraction nor the wider workflow should be described as independent of its configured model endpoint.

#### 4.7.1 Intent Classification & Compilation Variant Selection

Phase 1 uses only the Scientific Research lane. Phase 3 may classify exploratory research, code implementation, and formal specification requests. Multimodal classification and live priority re-ranking are excluded.

#### 4.7.2 Goal, Scope and Context Normalization

Phase 1 extracts goals/scope from supplied intake and local references. Phase 3 may filter larger repositories/historical context and derive non-goals. No live web augmentation of missing intake context.

#### 4.7.3 Ambiguity Resolution & Readiness

Phase 1 applies conservative fixed defaults and readiness checks without dialogue. Phase 3 evaluates bounded interactive clarification before dispatch. Do not invent unconfirmed user intent.

#### 4.7.4 Constraint Compilation

Compile stated resource, permission, data, security, and quality limits into the Research Brief. Enforce time/call bounds and reliable token limits through Runner/Gate controls. No dynamic hardware inference or autonomous permission negotiation.

#### 4.7.5 Task Contract & Acceptance Compilation

Produce the stable Research Brief with normalized objectives, inputs/outputs, constraints, user-level targets, and evidence obligations. Feed the fixed workflow in Phase 1 and Leader task semantics in Phase 3. No post-start contract rewriting.
