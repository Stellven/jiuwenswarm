## Summary
Implement a fresh Python compiler-only application with SQLite authoritative state, immutable named filesystem artifacts, a built TypeScript browser client, and authenticated REST/headless clients. No application code or existing web assets are imported. The fixed graph is Intention → protected deterministic checks → independent Intent verifier → durable Intent acceptance → Requirements → checks → independent Requirements verifier → durable Requirements acceptance → protected aggregate node release. Maximum four calls; no fifth review, repairs, retries, cached substitution, interactive clarification, or downstream research implementation.

Test-only fixture bridge is injected in Python tests and an explicitly labelled smoke profile; normal submissions cannot supply producer/verifier outputs or disable checks.

Provider strict structured-output transport omits optional diagnostic extensions and unsupported conditional keywords; the captured payload is checked against the unchanged complete authoritative schema and relationships, without content repair. Native transport retry caps are zero. Four observations count owned bridge invocations; provider-internal request count is not independently exposed and that limitation is retained in settings/evidence.
- Frozen safety choices (implementation settings, not claimed PRD thresholds): one active run, one model call per assignment, 120 seconds per call, 480 seconds aggregate, no retries; source/output size bounds and resource capture bounds configured by the operator. Actual memory-enforcement capability must be reported; unsupported mandatory limits block readiness, never claim prompt instructions enforce them.
- SQLite `synchronous=FULL`, transactions, persisted cancellation, monotonic revisions and acceptance records. Files captured with exclusive creation, SHA256 exact bytes, fsync and immutable identities; read/export verifies hash. Account/profile store outside workspace data. OS/GPU availability stays unmeasured unless explicitly supplied by protected configuration; `single_gpu` is declarative.
- Native feature: `docs/code/Missions/M0/M0-001`; all native helpers set `SPECIFY_FEATURE_DIRECTORY` explicitly. No extension file or project override currently exists. ## Interfaces and Technical Decisions
- [M0-IF-001@r1](TASK.md#4-embedded-cross-module-agreements): `/api/v1/readiness`, protected qualification/submission, request reconciliation, run status/cancel, named artifact and ZIP/manifest retrieval. Versioned field contracts are copied from the supplied catalog. Browser token is entered in local memory and supplied via Authorization header; never stored/exported in URLs. Scoped operator-provided credential/account/workspace mapping; constant-time token comparison and same-origin control. Private clients use the same gates.
- [M0-IF-002@r1](TASK.md#4-embedded-cross-module-agreements): immutable Intent 1.0.0/Brief 2.0.0 refs and Gate 2.0.0, child 1.0.0/node 2.0.0; accepted output records decide eligibility. Export may inspect candidates; consumer endpoint only obtains exact released Brief. Unsupported versions fail closed.
- [M0-IF-003@r1](TASK.md#4-embedded-cross-module-agreements): model adapter receives schema, protected instructions, allowed evidence and finite budget; returns raw response/settings/events/telemetry. Shell, MCP, browsing and apps are disabled for owned Codex calls; unexpected tool events halt. OS enforcement is independent from model instructions. No credential or release-state paths appear in model context. Auth readiness is not a successful semantic-model test.
- Intake confines supplied paths to a configured authorized root, rejects traversal, links/reparse paths and unsupported/oversized required sources. Original bytes are captured before decoding; `.txt/.md` exact UTF-8 text is preserved without universal-newline conversion, PDF original and extracted UTF-8 text are separate refs. Resource directories are read-only snapshots, never executed. Empty operator-created default document directory is allowed. Rejection records remain exportable.
- Admission validates actual local declaration/schema, implementation/dependency hashes, supported kind/ports, active standing, check profile and runtime capabilities. Synthetic architecture example admission is not reused as operational proof. Fixed prompt capsules have no arbitrary tools or filesystem authority; output capture belongs to host code.
- The effective external capabilities are the exact admission/template/parent/run-policy intersection. `resource_reads` and `write_roots` are empty at every layer: the capsule has no independent file/resource-reading capability. Protected host delivery of validated immutable typed input values over the audited model bridge is separate from external resource-read permission. The stable parent pins frozen role templates; no future artifact hashes or invented parent revision lineage is required. Every concrete binding rechecks complete body/dependency/schema closure, template/profile/ports and capabilities before dispatch.
- Every observed producer and verifier spend is counted before advancement or another dispatch; a selected aggregate token bound blocks on overrun or unavailable usage. This is an observed aggregate advancement check, not a hard in-flight provider-token cap. Final release also checks the budget and requires exactly the immutable observations already accepted by both internal gates.
- Criteria frozen before generation: Intent fidelity/coverage/consistency/Requirements usability; Brief preservation/default authority/coverage/planning usability, plus deterministic versions/ref/spans/IDs/default pointers/typed limits and actual completion/limits/pins/effects. Every criterion occurs exactly once with exact permitted evidence. Mechanical failure avoids the verifier; all mandatory nonpassing results halt. Node gate reuses Requirements assessment.
- Persistence failure never publishes accepted refs. Candidate files may survive a failed transaction but do not imply acceptance. Startup pauses running/queued records, does not replay. Cancel is persisted and checked before each dispatch/commit; owned process is terminated where supported; observed effects retained. A fresh submission may include an authorized previous_run_id, recorded as a provenance link without changing the prior run. No workspace deletion API is needed.
- Significant choices: standalone TypeScript UI instead of existing assets follows explicit user scope; protected evidence hashing follows benchmark/current architecture over older PRD wording (TASK unresolved/decision table). SQLite/filesystem instead of an external service enables bounded local inspection and fault tests. Container packaging is implemented even when Docker execution is unavailable.

## System Candidate and Journeys

Record HEAD plus dirty diff digest and SHA256 for relevant new/changed execution inputs, not HEAD alone. Integrated journey uses scoped readiness → intake → submit/client request ID → polling (or disconnect/reconcile) → three protected gates → consumer/exact Brief → export. Negative journeys preserve candidates and failure receipts, with no accepted external result. Full research DAG, scientific execution and benchmark suite are excluded.

Quality evaluation: labelled cases frozen before measurement; one repetition each demonstrates only those samples, not reliability. Record expected gate disposition, actual disposition, false acceptances/refusals, provider variability, requested/effective seed, elapsed time including all four calls, no hidden retries, reliable usage/null reasons. No unsupported rate/cost/latency target is introduced. Required model/deployment prerequisites constrain their checks; deterministic fixtures cannot substitute.
