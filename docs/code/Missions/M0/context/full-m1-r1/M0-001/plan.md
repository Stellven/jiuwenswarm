## Technical Context

- Confirmed repository runtime: Python >=3.11,<3.14; Pydantic v2 boundary models; existing TypeScript web/TUI; OpenJiuwen Git dependency pin `9e3390195a9ea15235b2b5f7412cb2aa440622cc`. Source availability/installed metadata does not prove runtime compatibility.

- Existing Codex subscription bridge is bounded text-only/read-only, with tools/web/apps disabled. Governed runner integration is new work; keep CODEX_HOME/process/thread/turn ownership separate from unrelated interactive sessions. Unknown delivery must not replay.

- Environment: repository `.venv`; scoped sandbox homes for initialization/security/cleanup checks; POSIX macOS/Linux operational acceptance and tmux require those platforms. Windows documentation creation is not platform acceptance.
- Performance/quality constraints: spec ACs only. Frozen fixture labels, independent expected results and scientific protocol thresholds precede execution; do not tune criteria from observed results.

## Interfaces and Technical Decisions

- Canonical owned agreement: [TASK §4](TASK.md#m0-if-001-at-r1) / M0-IF-001@r1. Consumers link it; generated implementation schema carries exact IF revision.
- Typed boundary: UTF-8 JSON and content-hashed artifact references; explicit schema/interface revisions and rejected unknown governance fields. Interface inventory and capsule migration requirements govern validation; a native Pydantic `extra=ignore` must not discard authority-bearing fields.
- Storage/evidence: release-essential persistence must commit before accepted output/readiness. Native cache, trace database retention or RSI event log is not authoritative release evidence. Optional diagnostics can be unavailable; required product views cannot be omitted and accepted.
- Failure/duplicate requests: reject changed payload under same request identity; reconcile transport response loss without execution replay; failures preserve exact subject/attempt; corrected work is a linked fresh run.
- Verification/gating: deterministic and independent semantic findings are separate from advancement policy; protected host aggregates/durably records final verdict and applies M1 release. Upstream result-evaluator/citation-reviewer logic informs profiles without gate authority.
- Unresolved exact implementation choices are work in owning blocks, not permission to relax requirements. Prefer Pydantic boundary types, existing Python/native UI/transport and bounded local state over new enterprise infrastructure; verify actual dependency semantics for swallowed exceptions/retries/caches.
