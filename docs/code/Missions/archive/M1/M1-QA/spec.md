## User Scenarios & Testing

### User Story 1 - Obtain the supported outcome (Priority: P1)
The authorized setup freezes four representative research-domain cases with visible inputs and independent protected oracles. In the adopted Docker environment an ordinary scoped client discovers/preflights,submits,reconciles,observes and retrieves each module path; RSI uses its separate session authorization/controller/referee. Independent scoring checks actual raw execution,committed actions and outcomes,including controlled invalid counterparts. Reusable adapters and versioned fixture/result definitions permit adding cases without changing product execution.
**Independent Test**: Use frozen source-valid inputs through the actual supported provider/consumer boundary and independently reconcile effects, exact identities, accepted artifacts and persisted evidence. Source/schema fixtures alone cannot establish real external connections.
**Acceptance Scenarios**:
1. Given valid inputs, admitted authority and ready prerequisites, when the scoped operation executes, then Four actual runnable containerized cases demonstrate Capsule,Evaluator/Verifier,Model Routing and RSI execution/evidence boundaries with genuine required model calls and independent referee,linked machine results/raw evidence,coverage report and reproducible commands. Correct no-improvement/inconclusive RSI is integration evidence without an improvement claim. Documentation,mocks,host-only tests,static route logs or unexecuted scripts cannot substitute for mandatory real execution.

### User Story 2 - Understand a failed or blocked attempt (Priority: P1)
The researcher or consuming module receives an attributable outcome when required validity, authority, evidence or resources are unavailable.
**Independent Test**: Supply a frozen invalid/boundary counterpart and inspect actual effects, terminal outcome and retained evidence against an independent expectation.
**Acceptance Scenarios**:
1. Given a violated mandatory condition, when the operation is requested, then Retain blocked,failed,timed-out,cancelled,interrupted and ambiguous attempts with explicit status and missing-evidence reasons. Reconcile uncertain delivery without duplicate submission. Missing runtime/model/custody/hardware/enforcement dependency leaves affected required integration incomplete,never passed. Unexpected advancement,hidden disclosure,evaluation tampering or unauthorized effects cannot count as full success.
2. Given missing mandatory real service or required unexecuted checks, when status is reported, then it remains BLOCKED, NOT_RUN or INCOMPLETE rather than PASS.

### Edge Cases
The AC table defines source-specific invalid, boundary, failure, cancellation, compatibility and recovery outcomes. Preserve failed/interrupted attempts. Unknown values remain unavailable, never zero. Reused identities cannot replace prior content silently. Missing mandatory evidence is not waived by a generated checklist or summary. Resource blockers constrain affected execution while independent preparation continues.
