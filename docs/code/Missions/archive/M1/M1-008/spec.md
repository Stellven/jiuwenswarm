## User Scenarios & Testing

### User Story 1 - Obtain the supported outcome (Priority: P1)
A human selects an admitted immutable parent and approved frozen target profile. The controller qualifies the opportunity, freezes the session, and asks an isolated proposer for bounded changes. Trusted mutation/parent-test checks precede protected scoring. The independent custodian/referee controls exposure and final comparison once against original parent. Only a qualified result can produce a signed candidate package for independent human-run admission, initially inactive, followed by distinct human activation/promotion/rollback controls.
**Independent Test**: Use frozen source-valid inputs through the actual supported provider/consumer boundary and independently reconcile effects, exact identities, accepted artifacts and persisted evidence. Source/schema fixtures alone cannot establish real external connections.
**Acceptance Scenarios**:
1. Given valid inputs, admitted authority and ready prerequisites, when the scoped operation executes, then The target-independent bounded offline loop, required rank_opportunities Target 1 pathway, custody/security/evidence interfaces and controlled candidate lifecycle are implemented with truthful status. A measured no-improvement or inconclusive session is an honest outcome, not a qualified child. Full independent/adversarial validation and operational activation remain separately evidenced and are not silently claimed from implementation or synthetic fixtures.

### User Story 2 - Understand a failed or blocked attempt (Priority: P1)
The researcher or consuming module receives an attributable outcome when required validity, authority, evidence or resources are unavailable.
**Independent Test**: Supply a frozen invalid/boundary counterpart and inspect actual effects, terminal outcome and retained evidence against an independent expectation.
**Acceptance Scenarios**:
1. Given a violated mandatory condition, when the operation is requested, then Forbidden mutation or security violation halts and preserves evidence; new optimization requires authorized human clearance. No headroom or missing readiness blocks the affected target. Inconclusive statistics, unavailable comparison, invalidated pins, infrastructure error and ordinary candidate rejection remain distinct terminal outcomes. Missing or tampered chain/signature/lineage prevents admission. No result changes live parent implementation automatically.
2. Given missing mandatory real service or required unexecuted checks, when status is reported, then it remains BLOCKED, NOT_RUN or INCOMPLETE rather than PASS.

### Edge Cases
The AC table defines source-specific invalid, boundary, failure, cancellation, compatibility and recovery outcomes. Preserve failed/interrupted attempts. Unknown values remain unavailable, never zero. Reused identities cannot replace prior content silently. Missing mandatory evidence is not waived by a generated checklist or summary. Resource blockers constrain affected execution while independent preparation continues.
