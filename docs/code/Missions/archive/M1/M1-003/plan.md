### Research decisions and alternatives

decision: Strict controlled-upload qualification before model use; retain original bytes and extracted text as separate Refs.; rationale: Prevents raw path/cross user run leakage and supports exact code point attribution; PDF parser does not silently rewrite original source identity.; alternatives: No document semantic dedup, vector store, OCR/Office scope expansion, raw caller filesystem traversal or current machine profiling.

decision: Use one canonical upload-time text extractor owned by M1-003 intake.py and invoked by M1-006 through ResearchService.; rationale: Reuse pdfplumber 0.11.9 already in uv.lock. Run extraction in a bounded process, record parser version/options and original/extracted byte identities, then store complete extracted UTF-8 bytes. Qualification verifies the stored bytes and text_sha256 without re-extracting, preserving source_ref and span identity.; alternatives: Do not add Poppler/pdftotext, a second PDF extraction path, OCR, network retrieval or model-generated text. The existing read_pdf agent tool's arbitrary-path and display-truncation wrapper is not the governed extractor.

decision: Two independently pinned work CCs and per-output semantic verifiers orchestrated within one parent compiler contract.; rationale: D5 authorizes fixed multi-pass; RequirementswaitsactualacceptedIntent. Parent finalizer is deterministic and has no third semantic interpretation.; alternatives: No single unverified JSON success, recursive verifier, auto repair or prior interactive chat reuse.

decision: Trusted producer/checks preserve coverage/defaults; D20/D24 semantic review remains declaration/output only. Challenge evaluation measures unsupported additions separately.; rationale: Span bounds do not prove entailment; no regex/numerical threshold can claim semantic fidelity authority beyond source.; alternatives: No work prompt/evidence replay to verifier under another field or fictitious full assurance.

decision: Keep fixed fallback noninteractive even web submission default interactive; invoke bounded intake questions only through available adopted advanced path, finish before Brief/planning.; rationale: M1-I003 and D48/D50 resolves interaction mode without introducing mid run waits.; alternatives: No treating client presence as permission, unbounded clarification or post start Brief mutation.

decision: Native ingest qualifies inputs without model work; submit allocates the run before compilation.; rationale: ResearchService.ingest returns the deterministic qualified intake_ref. The native client then uses ordinary submit, whose protected transaction commits idempotency and allocation before the compiler starts exactly once. Existing IF operation/path identities remain unchanged.; alternatives: No extra /intake endpoint, pre-submit model call or double compiler attempt.
