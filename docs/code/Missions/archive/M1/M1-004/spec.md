## User Scenarios & Testing

### User Story 1 - Obtain the supported outcome (Priority: P1)
An accepted Research Brief and captured baseline/validation resources enter bounded Search, fixed-rubric Screening, immutable Hypothesis design, confined Builder, deterministic baseline/treatment Benchmark, Scientific Evaluation and faithful Delivery. Each node produces candidates, required checks and per-output verification complete, and only durable advancing node decisions release downstream consumers. The same research contracts serve the static baseline and an admitted frozen planned graph without allowing experimental features to weaken Phase 1.
**Independent Test**: Use frozen source-valid inputs through the actual supported provider/consumer boundary and independently reconcile effects, exact identities, accepted artifacts and persisted evidence. Source/schema fixtures alone cannot establish real external connections.
**Acceptance Scenarios**:
1. Given valid inputs, admitted authority and ready prerequisites, when the scoped operation executes, then A valid Brief produces the named research artifacts, receipts, final report and manifest in the source-prescribed order under current admitted versions and effective budgets.; Measured positive, negative, inconclusive and pre-registered conditional outcomes are applied correctly; valid scientific negative/inconclusive results reach Delivery unchanged.; Every receipt run has an empirical row, explicit missing-metric status/reason when needed, raw stdout/stderr and exact protocol/configuration/resource attribution.; Only accepted, audience-authorized lifecycle artifacts are delivered, with resolvable exact content identities and reproducibility pins.

### User Story 2 - Understand a failed or blocked attempt (Priority: P1)
The researcher or consuming module receives an attributable outcome when required validity, authority, evidence or resources are unavailable.
**Independent Test**: Supply a frozen invalid/boundary counterpart and inspect actual effects, terminal outcome and retained evidence against an independent expectation.
**Acceptance Scenarios**:
1. Given a violated mandatory condition, when the operation is requested, then No evidence, no eligible idea, unavailable mandatory resource/lock, invalid artifact, missing required check, exhausted budget or violated confinement prevents affected dependent work and preserves available evidence.; Failed provisioning or failed/timed-out baseline produces no benchmark payload; treatment failure/missing output can produce valid unmeasured evidence and a scientific inconclusive result.; Changed frozen scientific rules/resources, prohibited imports or effects, invented measurements, altered report verdict, hash mismatch or blocking missing evidence cannot be repaired into a pass.; No autonomous retry, code-repair, rebenchmarking, model replacement or mid-run human wait is introduced.
2. Given missing mandatory real service or required unexecuted checks, when status is reported, then it remains BLOCKED, NOT_RUN or INCOMPLETE rather than PASS.

### Edge Cases
The AC table defines source-specific invalid, boundary, failure, cancellation, compatibility and recovery outcomes. Preserve failed/interrupted attempts. Unknown values remain unavailable, never zero. Reused identities cannot replace prior content silently. Missing mandatory evidence is not waived by a generated checklist or summary. Resource blockers constrain affected execution while independent preparation continues.

## Requirements

### Functional Requirements
- **FR-001**: Execute the admitted research CC chain from accepted Brief through Delivery. Each output is a candidate until protected acceptance. Run the deterministic bundle once over all work-subnode outputs; any mandatory failure suppresses every semantic-verifier call for that subnode. Otherwise verify each output separately under its exact declaration and accept a multi-output node only when all decisions advance. Persist candidates, accepted identities and evidence; preserve the one research chain in the static baseline. [PRD §§3.3–3.9, 6.6–6.9; Architecture_Design/pipeline/stages.md; capsule gate rules]
- **FR-002**: Search uses one bounded strategy-generation prompt to write its queries from the Brief within frozen search_scope. Capture and group retrieved excerpts by actual query before one single-turn idea-synthesis call; retained call/evidence records must demonstrate both responsibilities within the two-call ceiling. Use only scope-listed local_documents/arxiv/semantic_scholar connectors and the deepsearch operator; model calls are text-only. Scope has 1–3 unique connectors, max_queries 1–8, max_hits_per_query 1–5 per external connector/query, captured local refs, and 0–5 topic hints of 3–100 characters that are empty for static plans. Run each query once in sequence without reformulation; retain actual queries (1 to max_queries, each 3–200 characters, unique), exact captured source bytes, Unicode code-point offsets, excerpts of 1–2000 characters and excerpt hashes. Produce 1–3 ideas, each with an existing citation; record assumptions and risks. Search budget is hard 300 seconds, 2 model invocations and 20 connector tool calls. [PRD §§3.3.1–3.3.6; Architecture_Design/reference/capsules/search.md]
- **FR-003**: Perform one bounded scoring pass over incoming ideas using a pinned screening_rubric and exactly novelty, feasibility and compute_alignment, each integer 1–5 with five anchors. Keep one sentence per score reason, with length 1 through the configured reason_max_chars; that maximum parameter itself must be in the range 50-500. Apply forbidden dependency flags, including every host lowercase substring match across title/summary/assumptions/risks. Call pinned rank_opportunities for sum (3–15), descending total then ascending idea_id, selecting only Top-1. Produce screening_result and opportunity_card with unchanged scores/citations/assumptions/risks, all Brief constraint and mandatory-requirement text verbatim, and dispositions/reasons for every nonselected idea. Budget is hard 120 seconds, 1 model call, 0 tool calls. [PRD §§3.4.1–3.4.7; Architecture_Design/reference/capsules/screening.md]
- **FR-004**: Create one testable claim/mechanism and one intervention before code or measurements. Blueprint v2 includes every Brief target metric, exact baseline/validation snapshots, shared non-null prepared environment_ref, 1–8 unique metrics, measurement definition/unit/direction/aggregation/valid range, exactly one rule per metric, repeat_count 3–30, seed 0–2147483647 and fixed_same_for_all_runs. Implementation scope contains 1–5 change-scope items, max_patch_files exactly 1 and must_not_change baseline/validation_data/measurement_functions/outcome_rules; verification plan has 1–12 checkable steps. Carry all Brief constraints verbatim. Budget is hard 180 seconds, 1 model invocation, no network/tools. [PRD §§3.5.1–3.5.5; Architecture_Design/reference/capsules/hypothesis.md]
- **FR-005**: Protected preparation provides approved immutable environment_lock v1 with supported platform, full direct/transitive name==version requirements, reviewed package bytes, at most 500 unique package_refs and approval_ref. Resource snapshots preserve immutable revision, exact captured files, access/license/availability and compatible environment_ref. Resources are consumed from captured bytes rather than mutable origin locators. No package discovery/resolution/installation belongs to Builder or generated code. [PRD §§3.6.1, 3.7.1; Architecture_Design/reference/field-catalog.md#resource-snapshot, #environment-lock; platform dependency preparation; R5]
- **FR-006**: Builder consumes the frozen blueprint and captured resources/lock, writes requirements.txt, poc_patch.py and run_benchmark.py, packages exactly those three lowercase files in a nonpassword zip at most 1 MiB, and produces poc_manifest v2. Manifest pins the blueprint/environment/archive and each entry hash and declares at most 50 dependencies. It writes no empirical result, runs no trial and installs/discovers nothing. Host produces build_receipt from mechanical checks. Builder analytical output ownership stays with the corresponding research CC. Consume M1-001 one synchronous confined Codex call under executor identity, workspace-write, no tool network, approvals never and dedicated credential. Budget is hard 600 seconds, 1 invocation and 40 tools. [PRD §§3.6.1–3.6.5, 4.9.1–4.9.5; Architecture_Design/reference/capsules/builder.md; D43/D45]
- **FR-007**: Research Benchmark is a deterministic tool CC without a model. Trusted provisioning verifies accepted build readiness, unpacks confined content and installs exactly the frozen package set into a nonroot-owned venv under /workspace/poc/. Provisioning network is none or declared allowlist with no unlisted requests; measured runs have no network. Capture complete static hardware inventory once before the first run. Run repeat_count baseline executions before every treatment execution, with identical declared hardware/data/configuration/seed, preserving the baseline. Produce benchmark_payload v2, protected execution_receipt v1 and provisioning_receipt v1. Hard budget is 3600 seconds and 1 invocation. [PRD §§3.7.1–3.7.4; Architecture_Design/reference/capsules/research-benchmark.md §§2–4.3, 5–9]

Copy measurements from payload, protocol from blueprint, classification/findings and blockers/risks/notes/followups from saved verdict. All recommendation bullets appear only in section 8 and begin Recommendation:. Budget is hard 120 seconds, 1 invocation, 0 tools, no network. [PRD §§3.9.1–3.9.4; Architecture_Design/reference/capsules/delivery.md]
