### M1-C008 amendment to M1-IF-002@r2 - Aggregate library ceilings

User-approved change, 2026-10-16: use aggregate worker-plus-verifier ceilings while preserving worker limits and the overall run ceiling. This resolves the literal conflict between reference/run-plan.md:80 (LibraryEntry.max_limits equalling worker limits), :339/:432 (unchanged aggregate plan-to-node copy and verifier reservations inside that ceiling), reference/node-execution.md:15-17/:44 (independent checking inside the enclosing node), reference/field-catalog.md:223, and reference/model-routing-contract.md:120 (reserve independent checking before work).

For each eligible work CC, the protected library derives LibraryEntry.max_limits from its exact admitted worker declaration, exact independently admitted verifier declaration/admission, the subject's pinned checking_profile and all declared output ports. Let W_time be worker budget.per_call.wall_s and W_calls its declared audited_model_bridge invocation allowance (zero without that service). For each declared output, reserve V_time = min(verifier budget.per_call.wall_s, subject checking_profile.time_s), with exactly one audited verifier model call. Then max_limits.time_s = W_time + sum(V_time), max_limits.model_calls = W_calls + number of declared outputs, and max_limits.memory_mb is the maximum of worker and verifier admitted memory ceilings; serial memory is not summed. The verifier itself is mechanically checked without recursive semantic review and does not acquire another verifier reserve. An absent, unadmitted, ambiguous, non-one-call or incompatible verifier/profile pin prevents the affected work entry from being selectable. The protected snapshot closure identifies the verifier declaration/admission and subject check pins; changed inputs create a new immutable snapshot.

A proposal or authored static PlanNode.limits remains the aggregate work-and-check ceiling and is copied unchanged into NodeContract.node_limits under unchanged M1-IF-003@r1. Before work or model dispatch, the host reserves the frozen independent verifier allowances and sibling work still owed inside the node/run remainder. A narrower aggregate may narrow effective worker capacity; it never enlarges the worker declaration, borrows verifier reserves, or authorizes work when mandatory reservations cannot fit. The worker's own invocation/subnode limits and declared tool limits remain binding. Unused or suppressed verifier calls are actual unspent capacity, not fabricated usage. Missing/unreliable measurements retain source fail-closed semantics.

No record shape changes: library-snapshot and related source schemas remain 1.0.0. This is an IF002 semantic revision, not a new node/plan field or IF003 revision. Compiler and Planner pre-plan aggregates remain explicitly protected configured limits, containing their own worker and independent review reservations; no new numerical default is invented. Existing max_nodes 12, plan-policy aggregate 10800 seconds/80 calls/32768 MiB, source static aggregate 7200 seconds/60 calls/16384 MiB and max_attempts_per_node 1 remain unchanged. Author new pinned static-template bytes using the aggregate node allowances, check their sums/max against unchanged overall ceilings, and preserve all supplied source example bytes. Old affected library/static-template/run pins and evidence cannot establish current C008 behavior.
