# Usage scenarios and architecture sufficiency

**The design accounts for these outcomes; their runtime proof is NOT_RUN.** Three scoped cheap-model reviews challenged PRD bullets, reader portability and varied usage. Their agreement is not independent empirical evidence. This matrix retains the questions an implementer should resolve through the existing native feature's acceptance and evidence, without creating a parallel test card.

| Scenario | Required outcome and owner | Design authority | Review disposition |
|---|---|---|---|
| Normal text intent | Compiler preserves request meaning; separate verifier and protected commit release only exact accepted intent | [TRIAL-1](immediate-plan.md) | Designed; model-backed fidelity and challenge evidence NOT_RUN |
| Empty, conflicting or unsupported input | Reject or non-advance with reason; no invented constraints or hidden research expansion | [Ports](m1-design.md#research-path-and-ports), [callbacks](failure-and-human.md) | Designed; concrete domain/readability bounds owned by Spec Kit |
| Lost submit response / repeated client delivery | Reconcile client identity to the existing run; no duplicate compiler invocation | [Client contract](automation.md#client-contract-and-campaign-behavior) | Designed; actual reconciliation mechanism NOT_RUN |
| Browser closes, then process restarts | Browser loss does not cancel; interrupted execution is preserved/paused, not replayed; fresh corrected work gets new identity | [Lifecycle](workflow.md#scheduling-and-failure) | Designed; crash and uncertain-subprocess evidence NOT_RUN |
| Cancel while completion is in flight | Stop new dispatch, preserve actual effects and accepted evidence; committed run state owns the terminal outcome | [Callbacks](failure-and-human.md#when-to-call-the-human) | Designed; transaction/cancellation ordering belongs to native plan |
| CC suspended after freeze | Keep pins; revocation can block start/release; no substitute version appears in the run | [Lifecycle](capsules.md#library-lifecycle) | Designed; revocation-race checks NOT_RUN |
| Supporting CC fails inside a multi-CC node | Per-call evidence persists, authority stays scoped per CC; aggregate node cannot release incomplete obligations | [Node contracts](workflow.md#tasks-nodes-and-verification) | Designed; sibling containment realization belongs to runner task |
| Producer injects instructions or swaps artifacts | Evidence is untrusted data; exact contract/subject/check bindings and read-only review prevent release of unsupported content | [Verifier](capsules.md#exact-verification-boundary) | Designed; omission/injection/false-acceptance characterization NOT_RUN |
| Model unavailable, token telemetry absent, or budget exhausted | Missing provider blocks; absent telemetry remains unavailable; observable enforced time/call bounds halt, with no silent model switch | [Placement](placement.md), [shapes](contracts-and-native-reuse.md) | Designed; installed endpoint and limit behavior NOT_RUN |
| Gate says pass but artifact/decision persistence fails | No durable accepted readiness; orphan files grant no successor start; surface failure without claiming a persisted triage record | [Data ownership](m1-design.md#data-and-state-ownership) | Designed; partial-write/crash injections NOT_RUN |
| Scientific hypothesis fails | Valid measured negative/inconclusive science can receive infrastructure acceptance and reach truthful Delivery | [Research ports](m1-design.md#research-path-and-ports) | Designed; positive/negative integrated examples NOT_RUN |
| Advanced compiler needs clarification in headless mode | Only declared bounded pre-acceptance dialogue is interactive; headless never waits and unresolved material ambiguity halts | [Callback policy](failure-and-human.md#when-to-call-the-human) | Designed; Phase 3 dialogue/exhaustion evidence NOT_RUN |
| Profile conflicts or workspace is deleted | Stable account survives workspace; effective precedence is frozen; cloud profile storage never owns gates/local research data | [Identity placement](placement.md#deployment-and-boundaries) | Designed; concrete profile adapter/deletion proof NOT_RUN |
| Benchmarker asks to disable gates or mounts expected answers | Ordinary scoped client cannot change mandatory policy or access protected data; declared ablations are isolated and invalid for product/admission | [Automation](automation.md) | Designed; authentication/audience/isolation cases NOT_RUN |
| RSI child reads hidden cases or tampers with referee | Protected guard/oracle refuses and records violation; no score or producer assertion activates a version | [Offline RSI](offline-rsi.md) | Designed; guardrail/calibration/lineage evidence NOT_RUN |
| Producer supplies persuasive reasoning but deficient output | Review the exact artifact against independently assigned obligations; no replacement solution from the verifier earns producer acceptance | [Output-led review](guard-design.md#output-led-review-and-controlled-disclosure) | Designed; producer-narrative ablation and deficient-output challenge NOT_RUN |
| Required evidence contains credentials or disallowed provider data | Minimize/disallow disclosure before the call; no suitable route means blocked, not silent redaction followed by pass | [Evidence disclosure](guard-design.md#output-led-review-and-controlled-disclosure) | Designed; audience, redaction and leak-observation checks NOT_RUN |
| Guard tries a path escape, write or arbitrary network request | Enforce scoped immutable reads and deny effects; record violation and halt; a later pass cannot erase it | [Guard capabilities](guard-design.md#output-led-review-and-controlled-disclosure) | Designed; symlink, broker and effect-containment checks NOT_RUN |
| Planner omits checks or CC author self-approves a profile | Protected binder derives mandatory obligations from independently approved pins; unsupported coverage blocks, with no author override | [Ownership](guard-design.md#library-ownership-and-independence) | Designed; profile provenance/omission cases NOT_RUN |
| Same CC runs under a different protocol or policy | Rebind complete check plan and recompute observations/verdict; capsule-only or capsule/input caching never releases work | [Assignments](guard-design.md#assignments-and-check-plans) | Designed; cross-context stale-PASS challenge NOT_RUN |
| Implementer selects specification inputs | Current design and required source inputs are linked here; existing task/process authorities resolve in the repository | [Authority index](authority-index.md) | Repository-local link closure checked; runtime irrelevant |

The review found two handoff omissions: the POC module deny rule needed explicit acceptance meaning, and source links needed current coding authorities aligned to main. They are addressed in [the build boundary](placement.md#deployment-and-boundaries) and [authorities](authority-index.md). There is no known unresolved high-level outcome in this matrix. This does not certify all possible behavior or replace the PRD's exact scope bullets and required failure-injection cases.
