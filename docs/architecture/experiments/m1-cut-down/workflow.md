# Planning, binding and execution

Preparation is a protected fixed sequence before the research DAG exists. Intent, Requirements, Planner and their verifiers receive distinct node/attempt identity, admitted pins, input references and budgets through the same runner. No circular dependency on the plan being built.

Phase 1 statically injects accepted Brief parameters into the fixed SwarmFlow sequence. Phase 3 Leader/Team proposes bounded work and compatible admitted CCs; preliminary self-review cannot release a plan. Protected binder assigns contracts/checks independently, verifies requirement coverage, dependencies/typed ports, permitted effects, resource feasibility and acyclicity, then freezes the graph. No match blocks; no invented or installed CC.

Freeze exact library/dependency/guard/profile/policy/config pins and templates. Future values remain typed `{producer_node,port,type/version}` references until accepted; protected assembly finalizes concrete contracts before dispatch. Known-false preconditions block planning, value-dependent ones block dispatch when false. Suspension/revocation can block a pinned capability at start/release, but cannot replace it silently.

One node may invoke multiple admitted CCs under per-call authority/evidence/checks and node-wide limits. Protected aggregate node acceptance releases successors. Scheduler uses durable readiness; native memory/cache/queue is not acceptance. Single active research run and one sequential scientific path; no automatic repair, replay, replan or runtime library substitution.

Timeout/security/verification/persistence failure stops new dispatch and contains active work; preserve uncertainty/effects. Human correction starts linked fresh work with new freeze/checks. Scientific negative is not an infrastructure fault. [Contracts](reference/other-contracts.md) and [failure policy](failure-and-human.md) supply fields/outcomes.
