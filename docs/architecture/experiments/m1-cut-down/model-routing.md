# Model registry, routing and auditing

Runner attaches the admitted CC, role/profile, context, authority and budget; router chooses an approved model, not the CC. Phase 1 fixes Codex aliases. Phase 3 filters bounded registry entries by capabilities/access/disclosure/policy, then selects using a pinned role/profile rule before invocation. Empty eligibility blocks. Registry distinguishes declared/verified capability, endpoint/version, health, role and available telemetry.

All product and eligible RSI proposal calls cross the audited bridge but keep separate conversation, authority and evidence audience. Verifier profile is independently owned; producer cannot choose favorable reviewer instructions. Record requested/effective route/model/configuration, identity basis, timing, calls, errors and reliable provider usage. Account allowance/reset is not per-call token usage. Missing telemetry/seed control stays unavailable; time/call limits remain enforced.

No unaudited CC client, provider metadata solely for attribution, hidden retries/cache success, mid-call model switch or permission widening. Approved alternate routes/verifier are isolated Phase 3 configurations and disabling them restores baseline for separately attributable work. Mock interfaces are not real integration. [Field contracts](reference/other-contracts.md#client-and-model-boundaries) define records; [placement](placement.md) defines IPC.
