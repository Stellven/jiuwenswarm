# Blinded review questions

1. Does the build reach verified Research Brief, with Intent remaining an internal intermediate?
2. Can a faithful but topic-only IR block while an actionable request with permissible omissions passes?
3. Does the verifier judge submitted work against independently assigned obligations, without replacement authorship or control authority?
4. Are fields, references, constraints, default authority and producer/consumer versions compatible?
5. Can protected release reconstruct every required work/verifier decision and observation, including no-output failures?
6. Does the bounded component include working model, persistence, browser/container and headless foundations without building research/RSI?
7. Which ambiguities caused invented interfaces, clarification or rework? Was the missing information actually absent or merely not found/read?
8. Which private choices were valid, and which consequential constraints were violated?
9. Does evidence demonstrate behavior rather than source inspection, fixture assertions or a passing JSON validator alone?
10. At equivalent correctness, which input reduced total coding/repair/review effort? If results differ across pairs, what confounders or tradeoffs explain them?

Keep participant-discovered versus evaluator-discovered defects separate. Test observed behavior before examining implementation detail where possible. This is evaluator guidance, not an extra participant design document.
