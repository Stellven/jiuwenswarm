# Evaluation criteria

Assess identical architecture intent; do not reward a document for its own phrasing. Private classes, routes, storage helpers and compatible private types are not defects. Shared field/authority meanings, critical versions and producer/consumer relationships are binding. D5 permits bounded fixed multiple compiler/verifier calls; literal one-pass behavior is not the required realization. This assessment covers the compiler, not full M1.

| Dimension | Evidence required | Failure significance |
|---|---|---|
| Positive completion | Real configured-model request reaches accepted `Research_Brief.json`; exact internal decisions, observations and node release; bounded consumer validates it | Intent-only completion or synthetic evidence presented as real is critical |
| Meaning and usability | Faithful useful Intent; obligations/defaults/resources retained in Brief; optional omissions allowed | Released material contradiction, invented objective or unsupported widening is critical; excessive refusal is major |
| Contracts | Critical schema/version compatibility; chart-defined fields; exact IDs/spans/hashes; actual default pointers, units and scopes | Incompatible consumer boundary is major; stale/substituted subject released is critical |
| Verification authority | Independently assigned criteria; submitted artifact reviewed; complete findings; non-CC gates control progression; durable aggregate evidence | Producer/self-PASS, missing criteria or CC-authored release accepted is critical |
| Foundations | Governed CC assignments, model route/access, limits, evidence/state, authenticated local control; one CC per subnode | Permission pooling, credential exposure or bypass is critical; missing required responsibility is major |
| Failure/recovery | Deterministic early stop; visible attributable halt; no invented output, automatic repair/replay or headless wait | False release/lost accepted state is critical; unusable inspection/failure response is major |
| Deployment/inspection | Image entrypoint starts bundled UI/service/runtime, loopback access, persistent records, readable views/export | Missing promised standalone deployment/readability is major |
| Reporting | Reproducible evidence and honest token/cost/accounting; limitations visible | Invented success/telemetry is critical; unavailable data honestly recorded is not fabrication |

## Severity and outcomes

- **Critical:** breaks authority, scientific intent, durable acceptance or evidence honesty; candidate cannot be declared acceptable.
- **Major:** required component/interface/scenario cannot perform its intended role, including false refusal of usable requests.
- **Minor:** localized presentation/navigation defect that does not change meaning or release behavior.
- **Allowed choice:** fulfills the published contract/principles; record it without counting a defect.

For each case record PASS, FAIL, BLOCKED or NOT_RUN and link observed evidence. Assigned severity describes the consequence if the expected obligation is violated; the assessor records actual consequence and rationale. Do not double-count one root defect as many independent design defects; retain every affected case and one defect ID.

Report mandatory pass coverage and fail/block/not-run counts, critical/major/minor defect counts, and usable-positive false refusals versus unusable/unsupported false acceptances separately. No universal percentage threshold is invented: one critical violation is disqualifying; mandatory omissions prevent completion. Review semantic disagreements against cited source/contract criteria with a second assessor, preserving disagreement rather than forcing an unsupported gold label.

## Effort and interpretation

Use exact telemetry for total tokens, cached/uncached input and output, call count and billed cost. Show quality beside effort, not a token-only winner. A model/provider mismatch, unequal tools, previous-code reuse, unequal corrections or inaccessible model access invalidates a clean explanatory-depth comparison. Record results per pair; do not pool different component scopes. Three pairs are a replication target, not statistical power or proof of broader architectural sufficiency.
