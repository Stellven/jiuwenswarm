## Model router v1.7 against CC

**What changed from v1.4.** Only the catalog and the judge. Section 3.4 grew into an 87-entry "arsenal" (13 executor models, 65 scientific tool backends, 3 frontier, 6 references). Section 3.5 maps 17 proposed `domain.*` capsules to those tools. Anthropic Fable 5 was added. The judge became a fixed GPT-6.1 Sol call. The structure is unchanged: stage 1 selects a Capsule, stage 2 filters and judges a model, the route is frozen, the executor runs it.

**The conflict is real, and the router design is the outlier.** Three other sources agree with "the capsule comes first":

1. **The full PRD.** Both the 10-01 and 10-02 copies say the Router "reads" or "receives the DAG-provided capsule" and then picks a model (10-02, line 1494). The router design follows the older per-workstream PRD, which said "the Router first selects a single Capsule". The full PRD replaced that wording.
2. **The benchmark.** B2-fixed and B2 "use the same commit and library hash. They differ only in the router flag" (v5, line 179). The hypothesis is that the router "holds accuracy and cuts cost". If the router also chose capsules, the flag would change which capsules run, and the platform effect and the router effect could not be separated. The benchmark model-call tags already include `capsule_name` and `decl_hash` as inputs to the call, not as outputs of routing.
3. **Our own decisions.** D9 and D38, and the 10-01 consistency reply.

That is your point, now with the PRD and the benchmark behind it: the capsule decides the function, and the model only makes it cheaper, more accurate or more likely to succeed.

**Cost of the fixed judge.** The PRD said "lightweight" LLM judgment. v1.7 uses Sol. With dynamic routing, each decision with more than one candidate is a Sol call. The benchmark counts router-judge calls in cost (M6) and needs a 30 percent cut, so route per capsule call by default, not per turn. The single-candidate skip is already in their design.

## What the benchmark needs from the router seam

1. **A run-level router switch that leaves `decl_hash` alone.** Our reply pins the router in the capsule's Declaration. Removing the pin for B2-fixed would change the library hash. The existing proposal already avoids this: `cc.router.enabled` off means the runner's default model call ([environment](../system/environment.md)), and a router failure already falls back to the default model. So: the capsule always carries the pin, and the switch decides whether the router runs. That is the same hash with the router off. Say it in the proposal.
2. **The routing scope.** Our M1 rule says only tool capsules route; skills and gates use a fixed model. The benchmark expects the saving to come from planner and reviewer calls (v5, line 289). Under our rule there may be little to route. Question for Saurav: which calls does B2 route?
3. **Timing.** The benchmark needs the router live in AI4Research by T1 (about 2026-12-07). The full PRD makes routing an isolated Phase 2 track with mocked endpoints and no effect on Phase 1. Both can hold if the router runs on a branch for the benchmark. Someone should say so out loud.
4. **Tags.** Benchmark tags go in headers or metadata, never the prompt. D15 already says this.
