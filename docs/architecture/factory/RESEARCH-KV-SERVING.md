# KV reuse and serving research jobs

`engine.kv_reuse_lab` and `engine.serving_scheduler_lab` are self-contained native CC v2 packages under `jiuwenswarm/factory/ccs/`. Each owns run.py, reference.py, verification.py, methods, skill, source provenance and JSON examples. Only process.exec is declared; inputs are inline JSON. They do not route through or change the host factory API.

KV capabilities cover exact token prefix isolation/invalidation, paged reference counts with copy-on-write and safe release, and explicit MLA versus MHA/GQA storage estimates. Quantized sizing remains approximate and cannot authorize admission. Serving capabilities cover bounded FIFO admission, token budgets, chunked prefill with reserved fairness, decode rotation, frozen-workload arm comparison and estimated additive timelines. CPU token accounting leaves checkpoint routing unchanged; it is not proof of native output equivalence.

Use `fixtures/example.json` keys as capability inputs wrapped in `{"spec": ...}`. `verify` takes `{}`. The attached units are executable CPU checks and deliberately are not trusted factory cc_qualification units. `tests/factory/test_research_kv_serving.py` prepares each package and calls every capability through the real Host; no model runtime or GPU is used.

Pinned GitHub revisions and license metadata in each SOURCES.json distinguish vLLM, SGLang, llama.cpp, ro99/strata, DwarfStar and AdapMoE. Their primary source structures informed the methods; no upstream implementation is copied. AdapMoE adaptive gating is approximate expert skipping. PowerInfer-2 is a smartphone research system; the original PowerInfer repository cannot establish its implementation availability. None of these observations establishes ARM64/GB10/DeepSeek v4.1 support. Unified memory must be budgeted once with actual residency and workspace/OS reserve. Real kernel engagement, exact or admitted approximate quality, memory and performance need separate native experiments and operator-scoped qualification.
