## Overall assessment and handoffs

These are mostly native API façades, not independent executable implementations. The generic wrappers add a prefix and launch `python -m jiuwenswarm.factory.api` with a 49-second deadline (for example `ccs/builder/run.py:11`, relative to `jiuwenswarm/factory/`). Their actual behavior resides in mutable host Python modules and external workers. A sealed wrapper release alone therefore does not identify its complete runtime behavior. Qualification adds an explicit but partial local-source identity closure for one package/checker; it is not library-wide certification.

The intended flow is evidence/decision → inspection/integration → durable build → image admission → fixed-contract lab evaluation → retained result → agent decision. The newer loop offers a second route: evidence/methodology → operator-pinned complete template → child task → standard benchmark or scoped prefill adapter → collection/followup. A builder attempt is required by `lab_client.submit`; the standard benchmark route instead consumes the operator-frozen image and worker admission (`manager.py:38`, `benchmark.py:259`, `benchmark_worker.py:45`). These routes share Jobs, evidence storage and lab lifecycle infrastructure, but differ in contracts and admission receipts. They should not be described as one interchangeable evaluation API.

The current actual-run artifact is `/home/user2/software-factory-spark-20261113/results/agent-improvement-proof.json`. It records a real JiuwenSwarm agent, two controller generations, one screen cycle, successful configuration verification/admission, a stopped controller before measurement, independent raw-file verification and cleanup. The child execution succeeded but the scientific verdict was `scoped_correctness_failed`: baseline/candidate first tokens disagreed. Recorded median prefill times 4368.7/3211.6 ms (ratio 1.3603) are consequently **not an accepted speedup**. Supervisor outcome was `report_inconclusive`; no confirm run or promotion is proven. The artifact's `native_calls` includes evidence (27 calls), loop (8), qualification (4), inference-lab (4), and prefill workbench (4). It contains no direct builder, inspector, lab-client, lifecycle or standard-benchmark capsule calls. It demonstrates a bounded configuration/measurement/rejection handoff, not autonomous source synthesis or whole-library live qualification.

Historical responsibility documentation is expressly a map rather than proof: `docs/architecture/factory/RESPONSIBILITIES.md:9` contains Run 5 placeholders and `:39` says they make no measured reliability claim. Offline tests below substantiate implemented branches, not fresh GPU evidence or hardware reliability.
