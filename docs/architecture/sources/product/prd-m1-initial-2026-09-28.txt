# Product Requirements Document: AI4Research

## 1. Overview & M1 Objectives
AI4Research is an agentic scientific R&D workstation that automates the research lifecycle from literature retrieval and hypothesis generation to proof-of-concept implementation and empirical benchmarking. Built on a fork of `openJiuwen-ai/jiuwenswarm`, the platform couples deterministic Swarmflow execution with whitelisted tool operators from `openJiuwen-ai/deepsearch` and domain research skill logic ported from `openJiuwen-ai/sciencediscovery`.

The primary objective of M1 is to establish the core architecture and restricted domain functionality. While this document outlines the comprehensive feature set (including test report requirements and ongoing AI research tracks), M1 strictly bounds implementation to foundational scaffolding, whitelisted operators, and default deterministic states to ensure a rapid initial iteration. That being said, all functionality in the current AI4Research project will be either implemented, created but not wired in, or taken into consideration in the design to integrate in future milestone stages.


## 2. Domain Policy & Restrictions (M1)
To maintain velocity for next week's kickoff, the following policies govern M1 development:
*   **Static Defaults Over Dynamic Orchestration:** Complex components—specifically the Dynamic Planner Agent, RSI integration, and full dynamic Model Routing—are designated as **parallel development tracks**. They will not be coupled directly to the primary end-to-end execution path for M1 at the start so that we can debug and build a working workflow first.
*   **Decoupled Interface via Sample Artifacts:** 
    *   **Planner:** M1 uses a deterministic, hardcoded Default DAG. The Planner Agent will be developed concurrently against offline execution scenarios.
    *   **RSI:** Unblocked by operating on static sample DAG fixtures rather than live pipeline outputs.
    *   **Model Routing:** Restricted to a deterministic fallback/single-path router (via the Codex CLI adapter) while multi-model routing logic matures.
*   **Integration Gate:** No experimental autonomous behavior (dynamic replanning, self-reflection RSI loops) will be merged into the main release branch until baseline deterministic execution achieves stability in M1.

## 4. Component Details & Open Questions

### 4.1 Capsule Specification & Skill Sourcing
To accelerate M1 development and ensure high-quality domain execution, capability capsules are divided between ported domain blueprints and core pipeline scaffolding:

*   **Workflow Stage Capsules (Main Pipeline):**
    *   `requirement_capsule.md` *(Custom)*: Transforms natural language into structured JSON Research Briefs (objective, constraints, metrics).
    *   `search_capsule.md` *(Ported from `idea-tree-team`)*: Formulates research search strategies and clusters candidate directions, invoking the `deepsearch` local retrieval tool.
    *   `screening_capsule.md` *(Ported from `assessment-screening`)*: Multi-dimensional rubric scoring to filter candidate ideas.
    *   `hypothesis_capsule.md` *(Ported from `evolve-design`)*: Falsifiable hypothesis formulation and baseline experiment parameter setup.
    *   `poc_capsule.md` *(Custom)*: Bounded code-generation contract utilizing `CodeSearch` to output minimal test harnesses.
    *   `report_capsule.md` *(Ported from `report-writer`)*: Structured research report and delivery synthesis.

*   **Evaluator Gate Capsule (Transition Verification):**
    *   `verifier_capsule.md` *(Ported from `result-evaluator` & `citation-reviewer`)*: Powers the Tier 2 Semantic Verifier Agent within the Evaluator Gate, inspecting stage evidence bundles for claim-to-evidence integrity, schema conformance, and logical validity.

*   **Contract Standardization (`make_capsule.md`):** All capsules—whether executing workflow stages or gate verification—are wrapped inside standardized input/output schemas to enforce deterministic JSON payloads, bounded workspace paths, and review gate compatibility.

### 4.3 Evaluator Gate Architecture & Payload Specification
The Evaluator acts as a synchronous transition gate between Swarmflow nodes before stage handoff:
*   **Stage Evidence Bundle:** Packaged upon stage completion containing:
    1.  *Artifacts:* Generated text deliverables, structured JSON payloads, or code scripts.
    2.  *Capsule Contract:* Defined input/output schemas and acceptance rules (`make_capsule.md`).
    3.  *Telemetry Data:* Runtime metrics including token consumption against budget and exit status.
*   **Two-Tier Verification Pipeline:**
    *   *Step 1 (Deterministic Assertion Layer):* Programmatic Python checks validating JSON schema compliance, file presence, non-empty bounds, and token budget ceilings with zero LLM token overhead.
    *   *Step 2 (Semantic Verifier Agent):* Assesses qualitative alignment against capsule acceptance criteria (task relevance, logical coherence, deliverable completeness) and returns a structured JSON verdict (`PASS`, `FAIL`, `BLOCKED`).
*   **Gate Orchestration:**
    *   `PASS`: Advances Swarmflow execution to the subsequent stage node.
    *   `FAIL` / `BLOCKED`: Halts execution, records failure traces to the run tree, and invokes JiuwenSwarm's native HITL (`human_session`) prompt for developer triage.

### 4.4 Tool & Operator Architecture (`deepsearch`)
The platform decouples agent reasoning (Capsules) from concrete tool execution (Operators):
*   **Capsules as Contracts:** Capability capsules specify when and why an action is needed based on task state.
*   **Operators as Execution Tools:** Concrete actions are executed via whitelisted operators backed by the `openJiuwen-ai/deepsearch` suite:
    *   `DeepSearch`: Provides local document search and verified citations for research workflows.
    *   `CodeSearch`: Provides syntax-aware repository chunking and line-level code navigation for implementation workflows.
*   **Sandboxing & Security:** All operator invocations are mediated by JiuwenSwarm's native tool permission system, enforcing workspace isolation.
