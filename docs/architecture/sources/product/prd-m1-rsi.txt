### 3.Y RSI (Recursive Self-Improvement)

At M1, RSI takes one capsule whose author allows it (`evolution.rsi: propose`), works in an offline sandbox, and produces one child version that changes only what `evolution.may_change` allows, passes every test the parent passed and scores higher on hidden fixtures. A person activates each child or rolls it back. Target 1 is code mutation of the pure helper `rank_opportunities` (PRD 3.4.7) inside `screening_capsule`; mainline keeps it `evolution.rsi: none`, so M1 ends with a sandbox-proven child and its evidence report. Target 2 is text mutation of `screening_capsule`'s `SKILL.md` and `references/rubric.md`. The M1 goal is an engine that generalizes: both targets run through one capsule-agnostic loop core as two target profiles, and any other capsule (for example `requirement_capsule`) is an M1 stretch goal added as a new profile (Saurav's decision). Naming (proposed): M1 is capsule self-improvement, a fixed improver editing capsules; "RSI engine" names the term deliverable, which counts as RSI only if the changed part is the improver itself (proposer, operators, ranking and selection, suite author, how it reads observations), the improved improver runs the next round (not a fixed meta-tuner), the metric is improver quality on held-out improvement tasks (imp@k, `meta_test`), not capsule scores, and the referee stays out of reach of both levels; generalizing to more capsules or building new ones (build loop, M4) widens scope but is not recursion; all of it is weak RSI, since weights never change. M1 builds only the recursive layer's seams. Blacklisted items are deferred, not dropped, except two permanent ones: RSI never changes model weights or edits the referee (gates, verifiers, checks, sealed suites, policy, record stores). Status: Saurav's proposal, except the offline sandbox (AGREED 2026-09-29), "RSI never changes weights" and target 2's rubric numbers (Saurav's decisions). Reasons: `rsi-3y-full.md`.
