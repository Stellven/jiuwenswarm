# System Ontology 0.6.1 draft: dictionary

Generated by `tools/so_docs.py` from `ontology/dictionary.yaml`. Do not edit by hand.

One meaning per term. This dictionary defines the concepts: every file kind, every enumerated value and the main ideas behind the fields. What each individual field holds is in the [field reference](schema-reference.md). The Chinese name is given for reference; files use the English term.

310 terms.

## The ontology itself

| `system_ontology` | 系统本体 | The agreed way of describing an inference engine and the facts that determine what that engine should be. | `incompatible` | 接不上 | Checker result: two parts of a description do not fit each other. |  |  |

| `resolution` | 谁来定 | Who fixes a field of an engine spec: required (the requester), open (the factory may choose), resolved (the factory has chosen). | Not status. Status says how a fact is known; resolution says who decides a value. |  |

| `postponed` | 暂缓 | The component could apply but is left out of the first version, usually because its gain depends on something not yet measured. |  |  |
| `main_source` | 主要来源 | Marks an existing engine as the main source of a derivation: every one of its leaf components must be either carried over or listed as not carried. |  |  |
| `consulted_for` | 用途 | What an existing engine was consulted for in a derivation. |  |  |

## Given: model, hardware, environment

| Term | 中文 | Definition | Not to be confused with | Example |
|---|---|---|---|---|
| `model` | 模型描述 | The description of the computation to be run: its operations and the data they read and write. | Not the weight files themselves and not the engine. It says what must be computed, not how. |  |
| `operation` | 操作 | A unit of computation in the model, with the data it reads and writes. |  | expert_ffn: the feed-forward computation of one expert in one layer. |
| `compute` | 普通计算 | The ordinary kind of operation: it transforms inputs to outputs. |  |  |
| `selection` | 选择 | An operation whose result decides which other operations must run this time. This is how sparsity is expressed. |  | The router selects 10 of 512 experts per token per layer in Qwen3.8-Flash-Next. |
| `selects` | 选择范围 | On a selection operation: what it chooses among (`operation`, or `data` when the choice is of rows or blocks to read), how many exist (`out_of`), how many are chosen (`pick`), how often a choice is made (`per`), and optionally when the choice is known (`known`). |  |  |
| `draft` | 草稿操作 | A kind of operation that cheaply proposes later outputs. Its results are tentative until the full model has verified them. |  | The MTP layer that ships with Qwen3.8-Flash-Next. |
| `data` | 数据 | Something operations read or write. Either weight or model_state. |  |  |
| `weight` | 权重 | Data that does not change while the model runs: parameters and lookup tables. |  |  |
| `model_state` | 模型状态 | Data that changes as tokens are generated and must be carried from one step to the next. | Not the engine's own bookkeeping such as cache heat; that is engine state and is declared in the engine spec. | Attention keys and values; recurrent state. |
| `reads` | 读取 | X reads Y: X needs the content of Y and does not change it. Used for an operation and its data, and for a component and a state it does not own. |  |  |
| `writes` | 写入 | X writes Y: X produces or changes the content of Y. Used for an operation and its data, and for a component and a state it does not own. Every written state must have an owner. |  |  |
| `partitioned_by` | 可拆分维度 | The dimensions along which a piece of data can be stored and loaded in separate pieces. |  | Expert weights are partitioned by layer and expert, so one expert can be loaded without the others. |
| `encoded_bits` | 每参数位数 | The number of bits per parameter that the stated size of a weight corresponds to. |  |  |
| `serves_modality` | 服务的模态 | The input modalities an operation exists for. An operation that serves only image input is not loaded for a text-only task. |  |  |
| `work` | 工作量 | How much an operation actually has to process in a given step: how many tokens, rows or objects. | Not the size of the data. The same expert may process 2 tokens in one chunk and 400 in the next. |  |
| `hardware` | 硬件描述 | The physical capabilities of one machine: its compute units, memory pools and the paths between them. |  |  |
| `compute_unit` | 计算单元 | A part of the machine that can execute operations: a CPU, a GPU or an NPU. |  |  |
| `memory_pool` | 内存池 | A storage space with one capacity limit. Two things share a pool if using more of one leaves less for the other. | Not a device. A unified-memory machine has one pool for CPU and GPU; a discrete-GPU machine has two. | DGX Spark: mem0 (unified) and ssd0. A PC: vram, ram and ssd0. |
| `device_ram` | 设备内存 | A memory pool that belongs to one accelerator and is not shared with the operating system. |  |  |
| `host_ram` | 主存 | The main memory of a machine whose accelerator has its own separate memory. |  |  |
| `unified_ram` | 统一内存 | A single memory pool used directly by both CPU and GPU. |  |  |
| `nvme` | 固态硬盘 | Solid-state storage, described as a memory pool because data can live there and be read when needed. |  |  |
| `access_path` | 访问路径 | A way for data in a memory pool to reach a compute unit, with its cost. Either a unit using a pool, or data moving from one pool to another. |  |  |
| `direct` | 直接使用 | Kind of access path: a compute unit reads and writes this memory pool as its own working memory. |  |  |
| `direct_read` | 直接读 | Kind of access path: a compute unit can read a memory pool without copying, but more slowly than its own working memory. | Not an allocation kind. Data that is never kept in a pool and is read at each use has allocation read_through. |  |
| `transfer` | 搬运 | Kind of access path: data is copied from one memory pool to another. | Not a component role. A component that carries out such copies has role data_mover. |  |
| `page_in` | 换入 | Data moves from storage into memory when it is touched, managed by the operating system or by explicit reads. |  |  |
| `capacity_nominal` | 标称容量 | The capacity of a memory pool as the maker states it. | Not what an engine can use. See allocatable. |  |
| `allocatable` | 可分配容量 | How much of a memory pool an engine can actually obtain on a given machine at a given time, after the operating system and other software. |  | Strata's documentation reports 121.6 GB usable on a DGX Spark whose nominal memory is 128 GB. |
| `environment` | 环境描述 | What one particular machine actually offers at the time of a run: software versions and allocatable resources. | Not hardware. Two machines of the same hardware can have different environments. |  |
| `cpu` | CPU | A general-purpose processor. As a compute unit kind it names one in the hardware; as a resource kind it means processor time. |  |  |
| `gpu` | GPU | Kind of compute unit: a graphics processor. |  |  |
| `npu` | NPU | Kind of compute unit: a neural processing unit. |  |  |

## Engine: the spec and its aspects

| Term | 中文 | Definition | Not to be confused with | Example |
|---|---|---|---|---|
| `engine_spec` | 引擎规格 | A description of one engine for one model on one hardware, in nine aspects. A target spec states what is wanted; a resolved spec states what the factory chose. |  |  |
| `level` | 规格的层级 | Inside an equivalence: which of the four equivalence levels applies. | Not the level of a spec; that is spec_level. |  |
| `target_spec` | 所解析的目标规格 | On a resolved spec, the target spec it answers. |  |  |
| `boundary` | 产物边界 | The aspect of an engine spec that says what form the product takes (library, offline engine, service) and which responsibilities lie outside it. | Not the accounting boundary of a memory measurement; that is accounting_boundary. |  |
| `interface` | 接口 | How a caller uses the engine: input and output modalities, streaming, cancellation and errors. |  |  |
| `execution` | 执行结构 | The stages a request passes through and which activities overlap. |  |  |
| `stage` | 阶段 | A request-level step of execution. What happens inside a stage is described by the model's operations, not repeated in the spec. |  | load, prefill, draft, verify, commit. |
| `overlaps` | 重叠进行 | Two activities that run at the same time so that one hides the waiting time of the other. |  | Strata reads the n-gram rows for a token while the embedding and layer 0 run. |
| `state` | 运行状态 | What must be remembered while the engine runs: the model's own state plus the engine's bookkeeping, together with the rules for keeping it correct. |  |  |
| `states` | 状态列表 | The individual pieces of state an engine spec declares. |  |  |
| `scope` | 作用范围 | How widely one instance of a state, or one decision of a policy, applies: one request, one batch, or the whole engine. |  |  |
| `on_accept` | 接受时的处理 | What happens to a piece of state for the draft tokens the full model agreed with. |  |  |
| `on_reject` | 拒绝时的处理 | What happens to a piece of state for the draft tokens the full model did not agree with. |  |  |
| `keep` | 保留 | Commit rule: what was written during the check stays as it is. |  |  |
| `advance` | 推进 | Commit rule: the state is moved forward by the accepted steps. |  |  |
| `advance_by_replay` | 重放推进 | Commit rule: the state was not touched during the check; it is now moved forward by re-running the accepted inputs. |  | Strata's recurrent state. |
| `replay_records` | 按记录重放 | Commit rule: compact transition records made during the check are replayed for the accepted steps. |  | NInfer. |
| `restore` | 恢复 | Commit rule: the state is put back to what it was before the check. |  |  |
| `restore_then_append` | 恢复后追加 | Commit rule: the state is put back, then the accepted part is added again. |  | Strata's indexer keys. |
| `set_to_snapshot` | 设为快照 | Commit rule: the state is set to the snapshot taken at the last accepted position. |  |  |
| `recompute` | 重算 | Commit rule: the state is computed again from earlier state. |  |  |
| `invalidate` | 失效 | Commit rule: the state for those positions may no longer be read. Its storage may stay until overwritten. |  |  |
| `unchanged` | 不动 | Commit rule: nothing needs to be done because the check never modified this state. |  |  |
| `checkpoint` | 状态检查点 | A saved copy of a state kept so that a later request can continue from it. Declares how often it is taken and what must match for it to be reused. | Not the model's weight file. That is model_checkpoint. |  |
| `identity` | 复用标识 | The things that must be identical for a checkpoint to be reused, such as model version, token sequence and state format version. |  |  |
| `invariant` | 不变条件 | A condition that must hold at every moment whatever the engine chooses to do. | Not a requirement on results. An invariant constrains how the engine may behave internally. | A cache slot is not overwritten while a launched computation may still read it. |
| `policy` | 策略 | The aspect of an engine spec that holds the rules by which the engine changes its own binding or work amount while it runs. | Not binding. Binding is the arrangement; a policy is a rule that changes the arrangement over time. |  |
| `policies` | 策略列表 | The individual policies. In an engine spec, all the policies the engine runs; on a component, the ones that component is responsible for running. |  |  |
| `controls` | 控制对象 | What a policy is allowed to change: which item of which aspect, or which amount of work. |  |  |
| `signals` | 信号 | The observed values a policy reads to make its decision. |  | A usage count per expert, increased each time the expert is routed to. |
| `actions` | 动作 | What a policy may do, with the order of steps that keeps the invariants. |  | Mark the leaving expert absent, wait for launched work to finish, copy the entering expert into the slot, then mark it resident. |
| `trigger` | 触发条件 | When a policy runs or acts. |  |  |
| `budget` | 预算 | The upper limit of a resource a policy may occupy. Given as a value, or as a formula evaluated at startup. |  |  |
| `derive` | 推导 | A formula for a budget: a base amount times a fraction, minus what is pinned and minus a reserve. |  |  |
| `resolved_at` | 确定的时刻 | When a value becomes fixed: design (by the factory), startup (by the engine from the machine it finds) or runtime (by a policy while running). |  |  |
| `design` | 设计时 | Before the engine is built. As resolved_at it says a value is fixed by the factory. |  |  |
| `startup` | 启动时 | Once, when the engine starts. As a timing it says when something is done; as resolved_at it says a value is computed then, from the memory and devices actually present. |  |  |
| `runtime` | 运行时 | While the engine runs. As resolved_at it says a value is changed by a policy during operation. |  |  |
| `prior` | 初始输入 | The profile a policy starts from before it has observations of its own. |  |  |
| `parameters` | 可调参数 | The tunable numbers of a policy. Each is a value or is left open. |  |  |
| `binding` | 绑定 | The mapping from what the model needs to what the machine has: which implementation runs each operation, where each piece of data is kept, and at what precision. | Not policy. Binding is the arrangement; a policy is a rule that changes the arrangement over time. | Expert weights are all in host RAM and partly in VRAM; a cached expert is computed by the GPU, the others by the CPU. |
| `implementations` | 实现 | The available ways to run an operation: on which compute unit, reading from which memory pools. |  |  |
| `residency` | 驻留 | Where copies of a piece of data are kept, and what kind of occupancy each is. | Not where the data is computed. That is assignment. |  |
| `allocation` | 占用的性质 | How a piece of data occupies a memory pool: `pinned`, `reclaimable_mapping`, `transient`, `read_through` or `elastic`. |  |  |
| `pinned` | 固定占用 | The data stays in the pool and counts fully against its limit. |  |  |
| `reclaimable_mapping` | 可回收的文件映射 | The data is a mapping of a file. The operating system may drop its pages at any time and read them again from storage. |  | On DGX Spark, Strata uses the model file's pages as the expert cache. |
| `transient` | 临时暂存 | Space that holds data only for the duration of one computation. |  |  |
| `elastic` | 弹性占用 | An occupancy with a guaranteed floor and a cap it may grow to when memory allows. |  |  |
| `backed_by` | 数据来源池 | The memory pool the data really lives in, for a `reclaimable_mapping` or a `read_through` allocation. |  |  |
| `by_policy` | 由策略决定 | Marks a residency whose content is chosen by a policy while the engine runs. |  |  |
| `assignment` | 分派 | Which implementation computes an operation, under which condition. Entries for one operation are tried in order; the first whose condition holds is used; one must be the default. | Not residency. Assignment says who computes; residency says where the data is. |  |
| `when` | 生效条件 | The condition under which an assignment applies, from a fixed set: a ready copy in a pool, a transient fetch, held by another unit, or ranked low everywhere in the window. |  |  |
| `copy_ready_in` | 池里有可读副本 | Condition: the data the operation needs is present and readable in the named pool. |  |  |
| `transient_fetch` | 临时取用 | Condition: the data is brought into a staging area for this computation only and not kept. |  |  |
| `held_by` | 另一单元持有 | Condition: another compute unit already holds the data and computes the operation. |  |  |
| `all_ranks_at_least` | 排名都靠后 | Condition: every token in the window selected this object only at this rank or lower. |  |  |
| `otherwise` | 默认分派 | Marks the assignment used when no earlier condition holds. Every operation must have one. |  |  |
| `omit` | 省去不算 | The operation is not executed and contributes zero. This changes the output and needs an approximate-level mechanism and permission. |  |  |
| `precision` | 精度 | The number of bits per parameter a piece of data is stored at in this engine, when it differs from the model description. |  |  |
| `contract` | 契约 | What counts as meeting the request: the requirements, the allowed transformations and the workload they are judged on. |  |  |
| `requirements` | 要求列表 | The individual conditions the engine is judged against. |  |  |
| `quantity` | 量 | A measurable thing with a registered definition: its dimension and the fields that must accompany any requirement on it. |  | ttft must state where timing starts, where it ends and the workload. |
| `pass_fail` | 必须满足 | A requirement that must be met for the engine to be accepted. |  |  |
| `objective` | 优化目标 | A requirement to make a quantity as good as possible, with no pass mark. |  |  |
| `report` | 只测量上报 | A requirement only to measure and report a quantity. |  |  |
| `behavior` | 行为约定 | A requirement stated in words about how the engine must behave. |  |  |
| `candidates` | 候选值 | Several values put forward for one requirement that has not been decided. Each feasible candidate is solved as its own scenario. |  | 128, 80 and 12 GB for the first use case's memory budget. |
| `allowed_transformations` | 允许的变换 | The kinds of change to the computation the requester permits, such as placement, caching, numeric reordering or approximation. |  |  |
| `equivalence` | 等价 | How the output of an engine, a mechanism or a component relates to the output of a reference. One of four levels; where the level differs by condition, such as sampling mode, several cases are listed, each with its condition. |  |  |
| `equivalence_floor` | 等价下限 | The loosest equivalence level the contract accepts. A mechanism looser than this may not be adopted. |  |  |
| `bit_exact` | 逐位相同 | Equivalence level: the output is identical in every bit. |  |  |
| `distribution_exact` | 采样分布相同 | Equivalence level: individual outputs may differ but they are drawn from the same probability distribution. |  |  |
| `numeric` | 数值有微小差异 | Equivalence level: the same computation in a different order, so results differ in their last bits. |  |  |
| `approximate` | 近似 | Equivalence level: a different computation that is intended to be close. |  | Quantizing expert weights to 2 bits; skipping low-ranked experts. |
| `workload` | 负载 | The fixed pattern of use on which requirements are judged: what is asked, how long, how many at once. |  |  |

| `deliverables` | 交付物 | The things that must be handed over. |  |  |

| `batch` | 批 | Scope: several requests processed together. |  |  |

The factory has its own canonical vocabulary (`docs/architecture/design-package/glossary.md`). Agents inside the factory read both. This table lists every factory term that shares a word with one of ours and how the overlap is handled. Where it says renamed, the word now belongs to the factory alone.

|---|---|---|---|---|
| verifier CC | The general CC that assesses one output against its CC's declaration. | `draft_verifier` | renamed on our side | The engine component that checks drafted tokens was `verifier`; it is now `draft_verifier`. The stage name `verify` and the field `verifies` remain. |
| verifier subnode | One verifier CC call on one output. | `draft_verifier`, `component_ref` | renamed on our side | We no longer use the word node for an engine component. The component layer is the `component` file kind; the reference field is `component_ref`. |
