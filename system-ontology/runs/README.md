Each folder is the output of one run of a tool. Only the folders marked current are regenerated by
`python tools/so_run_all.py`; the others are kept as records and are not to be quoted.

In the run records under `muse-measured-2026-11-20` and `strata-measured-2026-11-20` the account name on the DGX Spark
is replaced by `<spark-user>`.

Why the earlier assessments and the first back-test are superseded. An audit on 2026-11-18 found that they:

- call their speed figures ceilings and their first-token times floors. Only the memory-bandwidth figure is an upper
  bound. The others hold only if each token's choice of experts is independent of the previous token's, which was
  not stated;
- tabulate an unevenness of expert use (exponent 1.2) that is not possible for a model that picks 8 different
  experts of 256;
- present the figures as an assessment of the design. No figure depends on the design's decisions;
- print conclusions that were fixed sentences ("Can it run? Yes"), whatever the inputs;
- report the back-test as agreement within 0.87 to 1.04 with no condition that could fail, comparing tokens per
  second with a figure per pass over the weights.

`muse-assessment-03` is the run that was in the package sent for review on 2026-11-17. `muse-assessment-04` differs
from it by one corrected remark and is superseded in the same way.

The record of the audit and of what was changed: `validation/criteria.yaml`, entries `audit_2026_11_18` and
`assessment_2026_11_18`.
