AI4R Hybrid v8: Same Observed Worker Accuracy, 18.19% Fewer Tokens

External presentation | measured and prepared 27 October 2026

18.19% fewer reported tokens, with both arms answering 24/24 assignments correctly. Hybrid v8 used 200,227 tokens versus 244,732 for fixed ChatGPT inside AI4R: 44,505 fewer tokens, including selection and independent verification overhead. All eight fixtures matched reference worker correctness. This is an observed result on a small development set, not demonstrated general accuracy equivalence.

1. Matched AI4R reference

The reference now uses subscription ChatGPT as the fixed worker inside AI4R. Both arms share the same model bridge, independent gpt-oss-20b verification and structural check. This replaces the historical direct-ChatGPT comparison for the current campaign. The report measures generated worker answers and component resource use, not end-to-end user delivery.

Method, scope and evidence

PropertyRecorded method
AssignmentsMR01: inference, retrieval, shortest path, performance, database, quorum, reliability and paired data.
SampleEight public development fixtures, each repeated three times in each arm; 24 observations per arm, not 24 independent tasks.
ReferenceGPT-6.1-Sol / medium as the fixed worker through AI4R, with the same independent local verifier and structural check as hybrid.
RoutingGeneral task-risk guards, then bounded gpt-oss-20b selection among eligible models; no case-ID or answer lookup.
ExecutionSequential isolated component observations through the actual production model bridge; no external tools or downloads.
Time envelopesWorker 90 s, including selector time when used; selector at most 30 s / 1,024 output tokens; verifier separately 60 s.
ScoringOffline exact JSON comparison with pinned reviewer answers. No LLM answer judge, answer repair or model-call replay.
Verifier inputDeclaration and produced output only; no original user input or reviewer answers.
ScopeRouter/model-bridge component comparison, not complete admitted research-DAG or frontend acceptance.
Hostgx10-004d / DGX Spark / NVIDIA GB10. Local models run on Spark; subscription inference is remote.
Timing limitsShared host, sequential arm order and overlapping application image builds; no controlled latency, peak-memory or power claim.

The policy and candidates were refined on these public development fixtures. Matching 24/24 observed worker answers is not a statistical equivalence result or a claim of general performance on unseen tasks. Different tokenizers and subscription wrapper overhead affect token comparisons. Monetary costs and savings were not measured.
