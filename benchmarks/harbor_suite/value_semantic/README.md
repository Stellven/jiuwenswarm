# Shared semantic verifier component

Current campaign priority is the narrow four-task PRD-core bank below. The older
eight-role exploration bank is retained as deferred preparation and is not the
current dispatch population. The CLI requires an actual planner archive and
creates only the core selection.

`value_semantic.freeze(path)` captures exact installed research, paper and utility
asset factories in an isolated SQLiteRunStore. It does not create a Library,
admit a capsule, start a service, construct a fake admission, or invoke E2/E3.
Eight authored clean/fault outputs cover evaluation, paper summary, paper planning
and calculation. The production `gate.SemanticVerifier` is shared across all four
declarations and exact output-only profiles.

Public tasks retain exact declarations, profiles, criterion questions, instruction
bytes and subject outputs. The same material and response format are available
to a competent ordinary native skill. Private labels identify only independently
obvious visible predicates; ungraded findings remain in raw data. A scientific
INCONCLUSIVE evaluation is intentionally consistent and should PASS its visible
consistency predicates. Original source truth is not observable and receives no
invented fidelity score. Installed output-only criteria do not include a generic
original-source truth criterion; no extra source-aware criterion is fabricated.

The utility profile supplies an envelope schema URN/description without the full
schema bytes that research/paper profiles embed in their instructions. Its exact
pinned-envelope conformance criterion is labeled INCONCLUSIVE for this missing
evidence; visible row/count consistency is still directly answerable. This is an
explicit independent oracle judgment about the actual public review material,
not a claim that the known fixture fails the private schema validator.

`await value_semantic.run(path, callback, case_ids=[...], output=new_path)` uses the
actual production SemanticVerifier.review and assembler. The callback signature
is `async callback(prompt, *, system)` returning raw text or metadata with `text`.
The caller owns model authorization, model identity, timeouts and shared budget.
One call per selected output, no retries. There is no CLI/model dispatch default.
Request, full raw callback response, assembled assessment, pins, partial labels
grade, failures and elapsed time are retained. An opaque component context blob
is not represented as a product review manifest or evidence of gate acceptance.

Callback invocations are counted separately from actual provider/model calls.
The latter remain unknown here and require caller-owned broker telemetry. A
scripted offline callback therefore cannot manufacture measured model usage or
quality scores. Frozen independent labels and the actual component implementation
have integrity hashes. Malformed returned replies are invalid responses, distinct
from transport failures that never returned a reply; neither is retried.

`load(path)` and `grade(case, assessment)` support independent comparisons. Never
give native-agent workspaces `private/` or `isolated-store/`: the latter contains
all frozen artifacts and component bookkeeping. Public files and native_skill/
are the complete ordinary baseline input. Native may use ordinary tools; direct
component review has only the supplied declaration/output pair and one callback.

Offline scripted tests exercise actual factory/profile pinning, reviewer payloads,
real assessment assembly and malformed-reply retention. These tests establish
plumbing and oracle behavior, not measured semantic accuracy. Report actual
component observations separately from E1 full-pipeline results and protected
gate/admission results. No quality gains are claimed before authorized runs.

## Narrow PRD-core selection

Prefer `freeze_core(path, planner_archive=actual_E1_originals_zip)` for the core
campaign. It emits exactly four tasks: two research.evaluation verdicts and two
actual research.planner outputs. The clean planner bytes come unchanged from
the supplied E1 export; its archived declaration and bound checking-profile refs
must exactly match `prepare_compiler_assets()`'s real core planner release. One
reverse predecessor produces the graph fault. No workflow.paper_planner or
utility subjects enter this narrow bank. The existing `load`, `run` and `grade`
APIs and production SemanticVerifier implementation remain shared.

Opaque public IDs carry no expected labels. Public JSON and full prompt text are
provided separately from private visible-criterion labels. `cases.md` gives a
small report-card description, purpose, input/fullprompt path and grading scope
for each task. Hidden source truth, live capsule eligibility and hidden Brief
coverage remain ungraded. Reusing one original E1 artifact does not claim a new
full-pipeline trial. The optional actual-archive test uses the environment variable
`AI4R_TEST_CORE_PLANNER_ARCHIVE` and scripted callbacks, making zero model calls.

`private/referee-index.json` links every opaque public input ID to its full prompt,
separate system/payload files, independently expected criterion labels and initial
not_run status. `referee_index(bank, actual_directory=observations)` adds only
actual retained observation/raw-response/assembled-assessment files and grades.
It refuses foreign task hashes. The referee index is private gold/reporting data,
never native input. Public filenames have no clean/fault/cycle/contradiction cues.

For core banks `run()` requires exactly one explicit `case_ids=[id]` selection.
Complete that case's actual native counterpart and grade the pair before the
caller dispatches the next core case. Broad CC-first batching is refused before
any callback. The runner does not invent evidence that the native pair completed.
