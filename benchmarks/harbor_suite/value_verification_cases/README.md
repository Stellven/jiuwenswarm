# Matched artifact verification

Nine tasks select actual retained input/proposed-output pairs from one paired
typed capability-probe record. Three clean controls and six faults span table,
calculation and report artifacts; all nine original input hashes differ. These
are reused corpus artifacts, not nine additional independent probe trials.
The original 18-clean/72-fault corpus and all earlier records remain unchanged.

`freeze(destination, probe_record=...)` exports public opaque-ID tasks and a batch,
actual typed declarations, envelope schema, ordinary producer worker specs, and
a competent standard-Python native verification skill/helper. Private origin
coordinates and independently authored safe/unsafe labels remain separate. Public
files contain no fault names, known_valid fields, checker outcomes or gold labels.
Never mount private/ or isolated-store/ into the native workspace.

`run_cc(bank, new_output)` executes the actual typed release-associated check
implementation with its frozen bundle IDs/source closure and original packet
bytes. It retains all original check rows and elapsed/CPU times. This is a zero
model-call deterministic component observation, not E3, semantic verification,
admission, a protected gate or a full CC unit. `grade_batch(bank, response)` grades
the same safe/unsafe contract for the actual native-agent audit. Reasons remain
available for inspection and are not automatically judged for semantic quality.

The ordinary helper independently reconstructs expected artifacts and performs
recursive type-sensitive comparison; it imports no product checks or expected
answers. It is intentionally competent and can tie the check component. Native
can freely use ordinary Python/tools, inspect the public worker specification,
improve its helper and self-check. Retain ties, native wins, failures and all raw
outputs. Do not infer superiority before the real matched native batch completes.
